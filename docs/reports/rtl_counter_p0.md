# P0：采集样本计数的 64 位身份

用户复核指出的 32 位限制在 `cosim/rtl/scanner_capture.sv` 中存在。本次将 sample_count 和
sample_out 改为 64 位；行内窗口位置、行号和忽略同步计数保持各自 32 位。没有改动冻结 legacy。
该模块是功能协同示范，不是可直接下载的 FPGA 工程。

在测试台将内部计数器初始化到 2³²−16，随后按原同步激励运行 64 个时钟。
斜坡、交替码和 PRBS 三种输入逐样本比对 Python 采集模型，样本身份跨过 2³² 后仍递增，
码字、行号、窗首/窗尾和被忽略同步计数保持一致。初始化仅用于测试，不是生产硬件参数。

新增独立测试台在采集窗尚未结束时复位，检查 valid 清除、样本计数从零重启、首行号重启。
复位前的计数跨过旧 32 位边界。测试台显式区分复位前后时期，协议包装层必须同步创建新 epoch，
不能把计数归零解释成同一时期的旧样本。

主机侧测试将**真实 Icarus 输出**封装成 ZLRAW，丢弃中间完整数据包，再接收后续包并加入复位后的
新 epoch：读取器检测包序号跳变，后续块的高 32 位保持；新时期从小序号开始，不误报同一时期回退。
断连后若采样继续，接收方必须保留源样本高位；若设备复位则必须新时期/会话，不能沿用旧身份。

这些验证支持组件功能与所测试的主机身份处理，不支持真实网口、DDR、DMA、引脚时序或整机采集结论。
本次也没有把窗口位置、行号扩大为无限长；32 位行号及 64 位样本计数耗尽前仍须结束或切换时期。
