# 控制历史检查点与恢复

2026-11-12，S3-T14，D047。`Controller` 新增版本化、带校验和的 JSON 检查点，
保存状态机、时期、完整控制记录与位置、下一命令 ID 和操作时间水位。
时刻以十进制字符串保存，避免跨工具转换丢失超过 2^53 的整数精度。

恢复从请求、生效、读回、状态和复位记录重新演算，比较全部派生状态和时期；
修改状态或游标后重新计算校验和仍不能绕过内部一致性校验。
同刻操作保留声明顺序，配置时期按采样时刻归属。
未来生效与读回是功能控制器的声明记录，尚未执行为真实硬件参数变化；
`readback_confirmed(at_tick=...)` 查询指定时刻，省略时查看全部声明。
这不等于实际硬件读回，不得标成 MEASURED。

## 本轮修复

- 请求先校验时刻、顺序和有限 JSON 值，再改变日志/时期。旧实现拒绝乱序生效前已写日志。
- 请求/生效/读回绑定唯一命令 ID；同值新请求不会继承旧读回，复位使之前确认失效。
- 复位早于已声明未来时期时明确拒绝，替代旧实现静默把复位推迟。取消计划接口尚未实现。
- 故障/中止标记当时有效时期为不完整，避免把已声明的未来时期误标为受中断。
- 保存的配置和各日志值分别复制，不受调用方修改输入容器影响。
- `split_by_epoch` 同步切分逐样本元数据，保留源身份，长度不符拒绝；旧实现整份元数据
  复制到每个片段，导致片段的码字与时间/标志长度失配。

## 验证与限制

单元测试覆盖所有十种可达状态的恢复与复位、未来读回、相同值多次请求、
拒绝无副作用、输入容器别名、元数据切分、校验和及重哈希后的不一致历史拒绝。
`tools/audit_control_checkpoints.py` 在每个可达状态声明一个未来生效/读回，
写检查点后在独立 Python 进程恢复、按时刻查询、复位和继续命令；
比较完整继续检查点字节并核对源文件哈希不变。

控制日志仍保留在内存中，大小随历史增长；检查点重演的成本也随日志增长。
模拟链、数字子链、控制和文件游标仍未组成同一个生产者原子检查点。
主 CLI 与工作台接入、实际物理参数生效和硬件复位行为仍待完成。
