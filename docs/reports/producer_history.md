# 原始数字操作历史

2026-11-13，S3-T14，D066。全部 SIMULATED / ORACLE_ONLY。

现有 events.jsonl 记录交付、损失等数字消费结果，没有保存接受的同步输入。
这些结果不足以重建任意历史采集窗口，不能拿最终队列状态冒充过去的状态。

recording 配置增加 `"record_digital_history": true` 可保存 producer_history.jsonl，
默认关闭，可以和 trace、record_quality 独立组合。同步输入带接受时的物理步号和原整数 ps；
advance 保存原物理区间、原源批次的序号/数量/时期及小端 uint16 码摘要；finish 保存排空操作。
每次操作保存实际数字链消费完毕的完整检查点摘要。保留原批次边界是为了复现同刻传输
调度顺序，不能随意改成逐样本输入后声称管线状态逐字节相同。

头部绑定源身份、通道、位宽、细步时钟、实际数字配置摘要和初始数字检查点摘要，
不新增或猜测任何硬件参数。每行有大小限制；同步和源分组最多各 4096 项，
一次记录推进最多 1,000,000 细步。历史按行流式读取，不一次加载全部记录。

统一物理根 v4 同时绑定 raw、诊断日志、可选探针/质量和本历史的提交前缀。
v1–v3 保持读取能力，缺少历史时不补造。恢复核对物理边界、运行配置和数字末态；
只读注册和历史物理重放也核对日志前缀。未知尾部只允许显式分支复制提交前缀，
不截断原件。写失败、数字链被绕过修改时不能提交已推进的新根。

`tools/audit_producer_history.py` 使用真实 CLI 创建连续、暂停/续写和未知尾部分支案例，
按保存原配置重算原源批次，逐码摘要、源时期和逐操作数字状态摘要全部比较；
并在新进程再次只读核对。原始文件及根要求逐字节相同，故障源摘要不变。
测试另覆盖质量开关、跨控制时期、故障写入、篡改和源不变。

本批次只完成原输入历史及其恢复/核对基础。任意 ps 的数字状态 API、预生成未来行与
实际在途行的区分、事件选择和统一游标仍在下一步；不声称浏览器交互、整阶段或实机验收。
这里的进程续写也不等于物理断电签核。
