# 数字队列检查点

2026-11-12，S3-T14 的传输组件。整链检查点仍未完成，D026 限制保留。

原 `simulate()` 将队列和事件堆封装在局部变量中，暂停后不能继续，且截止时会把下一事件
重新编号为 0。现由 `TransportSimulation` 统一实现批处理与分段运行，保存同刻事件原序号。
原函数仍保留为同一引擎的包装，避免两套不同的队列行为。

## 接口

- `TransportSimulation(stages, items)`：创建引擎；`items` 可省略，之后分批 `schedule(items)`。
- `advance(t)`：执行所有时刻不超过 t 的事件，关闭该时间水位；`advance()` 处理完所有已提交事件。
- `result()`：返回独立结果快照，查询或修改它不影响引擎。
- `checkpoint()`：返回版本化、含配置哈希和内容校验和的 JSON 字节；保存本身不推进状态。
- `TransportSimulation.restore(stages, blob)`：恢复，配置、版本或内容不符即拒绝。
- `drain()`：取走已交付/丢失记录及占用轨迹，保留当前队列、事件、峰值、最大等待和溢出计数。

检查点覆盖 FIFO 与入队时刻、服务中/被背压阻塞的项、字节占用、未来到达/完成事件、
同刻序号、时间水位、批次 ID 上界、尚未取走的输出与统计。JSON 供 Python 精确恢复，
不应先经 JavaScript Number 转换。格式是 `zlscan-transport-checkpoint/1`。

增量输入不能倒写已关闭时刻；同刻输入需先一起提交。每批 ID 唯一，后续批次 ID 必须高于
此前最大 ID，因此无需永久保留所有历史 ID 以去重。分数服务率按十进制有理数计算，再向上
取整到 ps，修正原实现先 `int(rate_Bps)` 的截断错误（例如 0.5 B/s 会产生除零）。

调用方应及时保存 drain 的记录。未 drain 时检查点会包含历史记录，不能声称大小与总输入无关。
该格式不包含 ADC 有效载荷字节、模拟滤波、采集窗口状态、控制事件或实际写盘游标；
文件写入也未执行 fsync，不构成断电恢复保证。

## 行为验证

先从提交 `7d0265e` 冻结 20 组原结果哈希，再改实现。冻结比较保持交付、丢失和占用轨迹的
顺序，仅将无序的 in-flight 守恒账本按 ID 排序。四种队列策略与五个截止位置全部一致。

36 个暂停位置恢复后与连续运行一致，覆盖同刻事件、服务中、背压阻塞、排队、未来到达、
下游主动丢弃和写盘故障。测试检查损坏/配置失配/版本拒绝、查询无扰动、分数服务率、
关闭水位及 ID 拒绝的原子性。2,000 批输入逐批 drain 后，检查点小于 2,000 B，
最大与最小大小差小于 128 B；测试同时核对实际交付 2,000 项且无在途或丢失。

`tools/audit_transport_checkpoints.py --out <new-directory>` 会将真实繁忙状态写入文件，
在新 Python 进程恢复，对比完整交付/丢失记录和统计。其时刻与源样本编号超过 2^53，
测试基于假设服务率与故障刺激，属于数字功能证据。它不证明硬件或整链恢复。
