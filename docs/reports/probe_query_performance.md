# 探针总览查询等值优化

2026-11-13，S3-T13/S7-T01 的服务查询部分，不关闭三套性能或浏览器门槛。

已有真实录制探针总览剖析发现：原始模式为 11,000 个细步逐点建立临时记录；
摘要模式无论目标层有没有数据都打开全部 116 个 HDF5 文件。
SHA 仍有显著成本；本轮保留前后文件校验，只优化临时归约和 HDF5 访问。

原始细窗保持原点；粗窗在每个有界读取片段中按现有显示桶归约，再合并跨块部分。
min/max/first/last/count、桶边界、原始请求/实际支撑范围、可见性/来源均不改变。
argmin/argmax 取首个等值极值，保留原逐点归约的有符号零，不能让 numpy min 的
等值零符号差异造成输出变化。没有增加响应缓存，不保存新的计算状态。

摘要模式通过全局桶的完成边界判断文件是否有本层数据。仅跳过不贡献数据的
HDF5 打开操作，原范围内每个文件仍做原有前后 SHA。注册时先核对所有块的
头绑定；重签但错误的头也在注册阶段拒绝。增加的注册检查有成本，不能藏在
热查询数字里。源文件未改变，存储/检查点格式也不改变。

新回归先观察到 2 失败/3 通过；优化后包括原始/摘要/物理恢复的 20 项通过，
进一步加头绑定负例及原导入边界共 167 项通过（5.71 s）。
细窗、非对齐窗口、两端裁切、单点、宽视图、跨块尾桶与两通道均与旧实现比较。

`tools/audit_probe_queries.py` 从上轮已归档的 raw/summary 完整合成源校验解包，
不依赖未入库的大输出；从固定 Git 提交读取旧 probe_store 源码，保存原字节与 SHA，
并确认其它 src 模块未变。共享同一个服务和冻结源，仅切换探针 Reader；
两通道 8 种窗口每种策略共 16 个响应，JSON 完全相同。读前/后源摘要相同。
基准查询分离注册/HTTP/JSON 编码/浏览器，旧新实现交替先后以减小顺序偏差；
真实测量仍受系统负载与 OS 缓存影响，不称冷盘或稳定 P95/FPS。
每种 Reader 注册另在查询后的热进程里做三次，包含所有源块验证，不混入查询时间。

本轮只改 probe_store 的读取路径；未优化仿真内核/端到端采集，未取消完整性检查，
不以短录制外推整幅性能。完整模拟质量事件索引、数字状态联动、浏览器、实机与
其它阶段 3–7 门槛继续保留。正式数据和当前安装包验证在后续结果补充。
