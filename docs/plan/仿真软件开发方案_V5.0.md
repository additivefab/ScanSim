## 0. 结论摘要

### 0.1 V5.0 的要点

1. **可视化方案的核心判断成立，采纳。** 要做到"停在任意时刻看每个节点、拖回过去轨迹不变、选中一个码字能找到它的采样时刻、放大到纳秒不把插值当观测"，缺的不是一个三维外壳，而是四样后端能力：任意时刻可查询、跨域时间可对齐、历史状态可恢复、样本去向可追踪。这些要求会反过来决定仿真的输出格式和状态接口，所以相关合同必须在阶段 0 冻结，不能留到最后。
2. **它提的 8 项收紧意见里，3 项在 V4.1 已经解决**（密度先转透射率、误差不能用 RMSE 相减归因、真值隔离测试的限定条件），其余 5 项本次采纳。它的建议条文 6 条全部采纳，其中 3 条做了调整（见 2.4 节）。
3. **我做的主要调整有三处。**
   - **高频模拟量默认不落盘，按需重算。** 可视化方案算过：20 路观察量全程记录约 76.8 GB。我的办法是每行存一个检查点，要看哪段就从检查点向前重放哪段。按旧模型单步耗时外推，重放一行约 38 毫秒（固定带宽）到 220 毫秒（电流相关带宽），这是外推，未实测。这样磁盘上只需要原始码流、事件、检查点和少量摘要。
   - **前端分三级交付，不一开始就上完整技术栈。** 第一级是每次运行生成的自包含离线网页（沿用包 B 观察器的做法），第二级才是本地服务加查询接口，第三级是可选的三维视图和安装包。合同与后端机制不依赖前端选型。
   - **事件字段沿用 V4.1 的三个正交字段**，不采用可视化方案里"测得 / 推断 / 仅仿真"的单一枚举，因为后者正是 V4.1 修订条款 P08 要拆开的东西。
4. **工期上调。** 各阶段估算逐项相加为 32–44 人周（V4.1 为 22–29.5）。增加的 10–14.5 人周全部来自工作台及其后端。可视化方案建议先对前四个里程碑做工作分解再重估，我同意；这里的数字只是量级，而且前端工作需要的技能与数值建模不同，很可能要第二个人。
5. **所有内容仍是设计。** 没有任何 V5 代码；性能与交互指标都是待验证目标。

### 0.2 沿自 V4.1 的结论

1. **审查包的意见绝大多数成立，V4 全部处置：36 项中采纳 34 项、部分采纳 2 项（A06、A15）、无一拒绝；另有两条总体主张（不给工期、不留任何估读数值）部分采纳。** 它补上了此前方案最薄弱的三块：真实板卡约束、"实机上到底能读到什么"的可观测性约束、以及有长记忆模型时的连续状态约束。
2. **审查包指出的几处过度推断，我核对后确认是我的错，V4 更正**（详见第 2 节）：
   - 把示波器游标差 4.28 V 当成"模拟输出摆幅"并据此判断 ADC 量程。
   - 从截图估读行周期约 0.7 ms。我重新放大原图后发现，屏幕上可读的 "80.0us" 前面的标签是 **W**（窗口时基），主时基 **M** 的数值被红色标注遮住了，所以连"每格 80 µs"都不能确定。该估读撤回。
   - 把载板上的"DAC控制"对应到 PMT 高压。
   - 把"复现 U 形底"写进验收。
   - 一边引入长记忆状态，一边声称行块可以独立并行。
   - 用均匀场标定送片向偏移（数学上不可辨识）。
   - 要求三路同步采集，而照片里的示波器只有两通道。
3. **审查包没有看到的内容，V4 保留**：它只审了 V2，没拿到两套代码，也没看到合并版 V3。因此两套实现的逐项对比与取舍、合并基线、交叉比对、可行性预算器的光子与几何部分，都来自合并版 V3 并继续有效。关于包 B 误差来源的说法按 P10 收紧：我做的是一次借助真值的配准消融，它提示对齐误差占重要部分，具体成因待独立实验分离（见 1.2 节）。
4. **实施顺序改为：证据与硬件画像 → 可行性预算 → 数字最小闭环 → 物理模型接入 → 标定重建 → 模型增强 → 实测。** 数字最小闭环提前，是采纳审查意见 C12：既然首要用途是算法与 FPGA 验证，就不该把它排在大量物理建模之后。
5. **逐行并行不作为性能前提。** 依据是一个外推而非整幅实测：用包 A 旧的固定带宽模型在小算例上测得每细步约 340 ns，乘以假设的总细步数 9.6×10⁸，得单核约 5.5 分钟；同一办法对旧的电流相关带宽模型得约 0.5 小时。**整幅从未执行过。** V4 完整模型、标定阶段、片外模拟、读写和双通道的开销，要用专门的性能场景实测后再定〔P10〕。在此之前，有状态链默认按时间顺序算，并行只用于独立实验和参数扫描。
6. **工期**：八个阶段，V4.1 时各阶段估算逐项相加为 22–29.5 人周；V5.0 加入工作台后为 32–44 人周（含可选部分）。这是计划估算，不是已执行事实，也不是交付承诺；每个阶段以门槛而非日期推进，实测阶段取决于资料何时到位。
7. **V4.1 合入的 12 条修订全部采纳。** 其中改动最大的五处：板端不得对对数码先平均再反对数（P01）；预算按采集模式判定，有限帧模式允许采集期输入高于出口（P03）；样本守恒改为按源样本身份覆盖检查（P04）；可观测性隔离测试与物理敏感性测试分开（P05）；旧行为复现与新模型正确性分成两套门槛（P06）。

### 2.4 可视化方案评审

**评审范围。** 我读了该文档全文，并复核了其中的算术。它声明没有拿到任何代码、波形或原理图，所以对 V4 中的运行结果一律按"文件报告的情况"处理，这个态度是对的。它附带的交互原型我没有找到，其中的合成场景、99.5 ns 演示时序、三个场景的守恒表都无法评审，也不作为本方案的任何依据。

**算术复核。** 以下均属实：

- 340 ns × 9.6×10⁸ 步 = 326.4 秒，约 5.44 分钟。
- 9.6×10⁸ 步 ÷ (7000×8600) 像素 ≈ 16 步每像素。这与包 A 的配置一致（每像素 2 个 ADC 样本 × 8 倍模拟细分），我在代码里核对过。
- 20 路 × 4 字节 × 9.6×10⁸ 步 = 76.8 GB。
- 假设 125 MSPS 时采样周期 8 ns，12 拍流水线为 96 ns。

**它不知道、而我能补充的事实。**

- 它担心"先在密度图上平均"的问题，并说明没有代码可查。我查过：两套包都是先把密度转成透射率再卷积，包 A 还有专门的测试。V4.1 已按 P09 写成约束。
- 它说 V4 没有规定 PMT 的渡越时间。两套包其实都有一个渡越延迟（示例 20 ns）加一个带宽极点（示例 8 MHz），但都是假设值，也都没有渡越时间分散和单电子响应。所以它的结论——快时间响应要做成可选层并标明假设——仍然成立。

## 4. 目标、用途与边界

### 4.1 用途

| 用途 | 典型问题 | 所需能力 |
|---|---|---|
| U0 可行性 | 几何参数自洽吗？高密度处还有多少光电子？数据传得走、存得下吗？ | 预算器，不运行仿真 |
| U2 算法与 FPGA 验证 | 接收位序、标签、缓冲、丢样标记是否正确？重建在标定不完美时是否稳健？ | 数字参考模型、RTL 协同、可观测性合同 |
| U1 设计权衡 | 采样率、光斑、带宽、增益、前端类型怎么选？ | 行为模型、参数扫描、像质指标 |
| U3 实测解释 | 高密度区偏高的原因是什么？ | 实测导入、辨识、独立验证 |
| U4 时序观察 | 某一时刻整机各处是什么状态？这个码字是哪一刻采的、走到哪了？这个像素受哪段输入影响？ | 统一时间轴的工作台、迹线、回放、因果追踪 |

优先级：U0 → U2 → U1 → U3。U4 不单独排序：它是观察另外四种用途的窗口，随每个阶段一起交付〔V01〕。

**新增目标〔V01〕。** 系统提供以统一仿真时间为核心的可视化工作台，联动展示光路、关键器件状态、光电与模拟响应、ADC 采样与输出、数字接收、缓存传输和成像过程。前端不得生成与后端状态无关的物理动画。

### 4.2 不做

整机光线追迹与镜头处方复原；晶体管级电路签核；引脚级建立 / 保持时序分析；可下载的 Vivado 工程；逻辑资源估算；DICOM 或检测规范合规；激光与高压安全认证；彩色负片颜色反演；板载显示等无关外设的电气仿真。

**"不做光线追迹"与"显示光路"的区别〔V23〕。** 第一版不做完整镜头处方求解和签核级光线追迹，但支持功能级光路和扫描几何的二维显示（三维为后续可选）。显示用的几何、候选光路、已验证的物理模型三者分别标记；浏览器里画的光线不是物理光线追迹。更高等级的光学计算通过可选模型或外部结果接入。

工作台第一版另外不做：逐光子全帧追踪、逐电子三维轨迹、拖动器件即实时重算光学的 CAD 式编辑、在线控制真实激光与高压。

### 4.3 两种配置模式

| 模式 | 规则 |
|---|---|
| `research` | 允许假设值和超出器件工作范围的外推，报告显著标注"超出硬件验证范围" |
| `hardware_constrained` | 器件等级、接口电平、时钟、接线、寄存器读回缺任一项即拒绝；未知值必须为空，不得从真值或默认值补齐 |

硬件约束模式原名 `hardware_verified`，按 P08 改名：它只表示"配置受真实实例资料约束"，不声明实机已通过。研究模式可以使用假设的硬件能力，但必须显著标注。

电气与接线检查使用三态：通过、失败、未决。"没发现冲突"不等于通过。

**模块级状态〔V07〕。** 整机的硬件约束门槛保持严格；另设模块级状态，例如"ADC 测试码功能模型通过""接口电平未决""模拟响应仅为假设"。这样缺少对数板资料时，数字链和工作台仍能在研究模式下推进。界面上不得用一个总的绿灯把局部通过显示成整机已验证。

### 4.4 五种"通过"分开

文档一致性、行为模型、RTL 协同、综合与时序、实机验证是五个独立状态。缺工具或缺输入的项写"未执行"或"未取得"，不以另一层的通过代替。

报告中分别显示：配置合规、行为模型、RTL 功能协同、跨时钟域结构与约束、综合资源、实现时序、实机测试。功能仿真通过不代替引脚时序和跨时钟域检查；仿真软件不重写静态时序或跨时钟域分析器，只接收并登记这些外部证据〔P07、P08〕。

### 4.5 整体完成标准

1. 重建与标定不读取任何真值，包括不经元数据间接读取；由隔离测试强制，测试条件见 9.2 节〔P05〕。
2. 两套门槛分开〔P06〕：`legacy_a`、`legacy_b` 预设复现包 A、包 B 的冻结结果；`v4_nominal` 预设按连续状态、可观测标定和当前接口合同验收。同一次运行不要求同时满足两者。
3. 数字参考模型与 RTL 逐位一致；每个丢失样本可追溯到层级与范围。
4. 同一全局时间轨迹在不同分块大小下输出一致。
5. 性能测试算例 7000×8600 在指定机器上的耗时与内存有记录（15 分钟 / 8 GB 为目标，不是承诺）。
6. 接入实测后，模型用独立于拟合数据的验证集检验。
7. 工作台：所有视图由同一个运行、时期和时间游标驱动；反复拖动返回相同记录；没有记录的区间显示为未记录而不是插值；打开或关闭探针不改变仿真与重建结果〔V24〕。

## 5. 总体架构

### 5.1 数据流

```text
资料证据 ──→ 硬件画像 + 实验计划 + 经校验的配置
                     │
        可记录的控制命令、测量设置、实验时间线
                     ▼
┌──────────────── 真值世界（私有）────────────────┐
 底片 → 光源 → 扫描几何 → 光斑/眩光 → 集光 → PMT
     → PMT 到前端的电气路径 → 对数/线性前端 → 二级主放/耦合/滤波 → ADC 转换
└────────────────────────┬────────────────────────┘
                         ▼
        ADC 输出链路：输出格式、数据时钟、位序、接收、跨时钟域
                         ▼
   可观测出口：码字 + 真实可测事件 + 配置记录 + 丢失记录
                         ▼
   数字参考模型 → 多级队列/存储/传输 → 原始数据集
                         ▼
        标定（→ 标定文件）→ 重建 → 图像 + 质量掩膜
                         ▼
   评价（唯一能读真值的地方）→ 密度/MTF/噪声/条带/几何/完整性
```

**真值的读取权限〔V15〕。** 能读仿真真值的只有两方：评价器，以及授权的只读研究探针（供工作台的研究视图使用）。标定、重建和真实硬件控制不得通过接口、元数据、共享状态或导出文件间接读到真值。研究探针走独立的数据路径和接口白名单，不是在页面上隐藏一个选项就算隔离。

```text
仿真内核
   ├─ 合法可观测出口 ──────→ 标定 / 重建 / 原始数据
   └─ 只读研究探针
          ↓
      观测代理：信号注册表 · 迹线与事件索引 · 检查点与命令日志 · 时间窗查询 · 样本与像素因果关系
          ↓
      查询接口 → 统一时间游标 → 光路 / 波形 / 逻辑 / 图像 / 探针
```

### 5.2 可观测性合同

重建与标定只能用实机上确实读得到的东西。

| 数据 | 可交给重建的条件 | 默认 |
|---|---|---|
| 原始 ADC 码、溢出标志 | 通道与接收模式已声明 | 可用 |
| 行同步时刻 | 有实际信号，并按真实同步器 / 时间戳方式采集 | 探测器未确认时不可标为实测 |
| 编码器计数 | 有硬件且计数含义已知 | 空 |
| 镜面号 | 有独立传感器读出，或由算法推断并允许失锁 | 空；区分"测得"与"推断" |
| 真实光点坐标、真实光斑、真实 PMT 增益、真实激光功率 | 永不 | 仅供评价 |
| 控制 DAC 码 | 命令与生效时刻可记录 | 控制去向未知 |
| 激光参考光 | 确有参考探测器及接线 | 不存在；第二 ADC 通道不自动成为参考光 |

每个事件至少带三个互相独立的字段〔P08〕，另有来源、不确定度、时钟域、时期编号和能力依据：

| 字段 | 取值 | 含义 |
|---|---|---|
| `origin` | `SIMULATED` / `MEASURED` | 数据来自仿真还是实机 |
| `visibility` | `OBSERVABLE` / `ORACLE_ONLY` | 实机接口上能否读到 |
| `derivation` | `SENSOR` / `INFERRED` / `COMMAND` | 传感器读出、算法推断，还是控制命令记录 |

枚举是建议规格，以最终冻结的数据格式为准。三个字段不能合并成一个：仿真出来的行同步信号是 `SIMULATED` + `OBSERVABLE`，可以交给重建，但不称为"实机测得"；真值镜面号是 `ORACLE_ONLY`，不得交给重建；算法推断既可作用于仿真观测，也可作用于实测观测。`ORACLE_ONLY` 事件单独存入真值文件。

### 5.3 四种窗口

| 窗口 | 含义 |
|---|---|
| 光学窗口 | 光束实际能扫到的范围 |
| 底片掩膜 | 底片与片夹占据的空间 |
| 数字保留窗口 | 数字链保留并上传哪些样本 |
| 输出区域 | 最终图像范围 |

四者独立配置。片外强光即使不上传，也先推进 PMT 与前端状态，再按数字保留窗口丢弃输出。底片宽度占比不等于上传占空比。

### 5.4 多速率时间

用全局单调时间加各域计数，不强行统一步长。

| 时间层 | 内容 |
|---|---|
| 控制事件 | 配置、复位、光门、送片、增益变化 → 时期编号、标定有效性 |
| 光机与模拟细步 | 角度、片位置、光功率、透射积分、PMT 与前端状态 |
| ADC 采样孔径 | 取差分输入，量化 |
| ADC 输出事件 | 按模式与流水线把样本放到引脚 |
| FPGA 接收拍 | 位序、跨时钟域、有效窗口、标签 |
| 系统服务事件 | 缓冲、DMA、存储、传输、主机落盘 |
| 行与帧事件 | 行同步、样本数、缺行、排空 |

样本以"采样序号 + 时钟域"为时间依据；网络到达时刻另记，不作曝光时间。

**时间表示〔P11〕。** 用域内整数计数加明确的跨域映射表示时间，不用一个很大的绝对浮点时间代替所有采样序号。同一时刻发生的复位、采样、入队、出队、行同步等事件，按确定且带版本号的调度规则排序。

**延迟分类〔P02〕。** 以下五类分别建模、分别记录，同一物理机制只计一次：

| 类别 | 产生位置 |
|---|---|
| 纯传输延迟 | 光程、PMT 渡越、线缆 |
| 滤波器相位与群延迟 | 由各动态环节的状态推进自然产生；不再另加一个同源的经验延迟 |
| ADC 孔径与流水线 | ADC 转换与输出链路 |
| 数字接收延迟 | 接收、同步器、标签对齐 |
| 队列与网络到达延迟 | 只描述传输，不参与曝光时标 |

### 5.5 连续状态

每个有记忆的模块提供四个操作：初始化、推进、存档、恢复。状态包括滤波器、PMT 增益恢复、耦合电容基线、对数级动态、光源漂移、有色噪声、运动。

- 行起点与行同步不重置模拟状态。
- 暗、白、阶梯、样片属于同一条实验时间线，除非实验中确有复位或长时间稳定。
- 一个块的终状态是下一个块的初状态。
- 数字复位不自动代表 PMT 或模拟电路复位〔P11〕。

**快照内容〔P11〕。** 存档必须覆盖：模拟状态、运动与漂移、随机数及有色过程的状态、事件队列、各类计数、ADC 流水线中的在途样本、所有数字队列、数据格式的时期，以及写盘游标。缺任何一项，恢复后的运行都可能与连续运行不一致。

### 5.6 并行与分块

- 有状态链默认按时间顺序推进。性能依据只是外推（见第 0 节第 5 条），整幅未执行；若专门的性能场景实测不达标，再评估有误差界的分块方案。
- 并行用于：独立实验、参数扫描、不含状态的底片与光学预计算。
- 空白区解析推进：只对线性环节且输入恒定时使用；预热长度 T 由误差上界 `Δs·exp(−T/τ)` 决定。电流相关的非线性环节不套用该公式，只能逐点计算或延长活动区。
- 空间卷积的邻域与时间状态的预热是两回事，各自做块边界测试。

### 5.7 随机数

- 白噪声与局部事件：由"物理源标识 + 全局样本序号"派生。
- 慢漂移、转速游动、1/f 过程：用连续状态或全局预生成轨迹。
- 三项验收同时满足：改变分块与并行度结果不变；跨行相关与频谱正确；总统计量正确。

**噪声与时间箱〔P09〕。**

- 一个时间箱内的光电子数，服从与该箱曝光积分一致的计数分布。
- 每个噪声源的配置写明单位，以及是谱密度还是某一时间尺度上的积分方差。
- 改变模拟细步，不能无依据地改变固定曝光窗内的物理统计量。包 B 在采样点独立加输出噪声，采样率一变噪声带宽就跟着变，V4 不沿用这种做法。
- 某一路散粒噪声已由计数抽样产生时，同一路径上不再叠加同源的高斯近似。

### 5.8 三种计算模式

| 模式 | 定义 |
|---|---|
| `fast` | 确定性均值 + 标明适用范围的解析噪声近似，用于参数筛选 |
| `full` | 按细时间单元抽样光电子数与倍增统计，保留完整状态；不建立逐电子事件表 |
| `event` | 短片段、低计数率、单电子响应研究；单独限制资源 |

三种模式的噪声处理要么互斥，要么按经过验证的规则组合，不能在同一路径上重复计入同一噪声源〔P09〕。

### 5.9 配置

五棵树：`truth`（真值）、`instrument`（仪器认知）、`hardware`（板卡与模块）、`experiment`（实验时间线与产品需求）、`observation`（测量仪器与测点）。`instrument` 与 `hardware` 中的未知项不得从 `truth` 补齐。

每个参数保存：数值、单位、证据类别（项目文本 / 图片观察 / 原理图标称 / 外部手册 / 设计推导 / 假设 / 实测）、来源与定位、不确定度、适用范围、测量时间与方法、状态。未知用空值，不用零。

另有：
- 约束求解：面数、转速、焦距、像素间距、采样率、每像素样本数、占空比不能各自独立赋值。
- 旧配置转换器：包 A、包 B 配置转为 V4 配置。
- 性能测试算例与产品需求分开存放。

审查包的 `硬件配置草案` 与 `requirements.json` 直接作为 `hardware` 与产品需求的起点。

### 5.10 标定文件

- 来源状态：`MODEL`（真值导出）、`SIMULATED`（由仿真的标定扫描估计）、`MEASURED`（实机）。重建默认拒绝 `MODEL`；它只在明确的旧行为兼容测试中许可，不能据此取得新模型的物理正确性或实机验证状态〔P06〕。
- 绑定：硬件实例、接线版本、固件与寄存器校验值、通道角色、增益设置、时间与条件范围。应用前做兼容性检查；失配或过期只能研究性使用并显著标记。
- 内容：暗值、逐列（逐面）白值、码值到相对光强的查找表、延迟、几何映射、逐面校正，及各项不确定度。

### 5.11 数据格式

| 层级 | 必需信息 |
|---|---|
| 会话 | 格式版本、硬件 / 固件 / 接线 / 寄存器 / 标定校验值、通道角色、时钟定义 |

**数值域〔P01、P12〕。** 每条数据流声明：数值域（原始码、线性信号或透射率、密度、展示图四者之一）、标定标识、单位、输出位宽、合并权重、无效数据策略。四种数值域分别定义、分别存储，不混用。

**源样本身份〔P04〕。** 源样本用（运行、分支、会话、时期、时钟域、通道、采样序号）唯一标识〔V17〕；行号、镜面号不能代替。每个样本保存四个时间：被采样的时刻、ADC 输出有效的时刻、FPGA 捕获的时刻、主机收到的时刻，不合并成一个时间字段〔V12〕。抽取、聚合、压缩、重采样等变换记录其输入范围、选点或权重规则和输出项。重叠的滤波或插值要建立依赖或覆盖关系，避免同一源样本被重复计数。

兼容包 B 的无头行优先小端格式作为最简输入。具体字节布局须与 FPGA 侧共同冻结。校验错、长度不符、未知格式版本、序号倒退、重启后时期变化，一律不静默拼接。镜面号、行号、包序号在复位后会重复，必须与会话和时期组合才唯一。

### 5.13 时间查询与回放合同〔V01、V10–V14〕

**模块声明。** 每个模块除初始化、推进、存档、恢复四个操作外，还要声明：可观察的状态、信号单位、时间语义、记录策略、来源。每个启用的物理模型另补一份实现规格〔V02〕：

| 规格项 | 内容 |
|---|---|
| 接口 | 输入输出及单位 |
| 状态 | 状态变量与初值 |
| 方程 | 数学形式与数值更新方法 |
| 参数 | 每个参数的来源与证据状态 |
| 适用范围 | 带宽、幅度范围、误差控制方式 |
| 验证 | 对应的解析算例或交叉验证 |

V4.1 列出的"对数级电流域状态方程""PMT 下垂""任意极零点滤波"目前只有名字，实现前先按此表写出规格。

**三种显示语义，不混用。**

| 语义 | 回答的问题 | 做法 |
|---|---|---|
| 同时刻观察 | t 时刻整机各处分别是什么状态？ | 每个组件显示它自己在 t 时刻的值。PMT 在响应稍早的照明，ADC 在采当前输入的同时输出更早的样本，主机可能还在收上一行。这些错位如实保留 |
| 样本跟踪 | 这个码字怎样从采样走到主机？ | 选中一个样本，显示它在数字链各处的时间戳。不为了让箭头齐步走而把各段延迟画成一样 |
| 因果回溯 | 这个像素或码字受此前哪些输入影响？ | 线性环节用响应核给出依赖窗口，截断长尾时给出截断误差。非线性环节只显示已定义的依赖范围或扰动分析结果，不伪造线性权重 |

一个 ADC 样本依赖此前一段光功率和前端状态，不是唯一的一个光子；一个像素通常对应多个 ADC 样本。界面上三种语义各有明确的模式名。

**四种时间精度同时标明。**

| 精度 | 含义 | 例 |
|---|---|---|
| 表示分辨率 | 时间戳能表示多细 | 1 皮秒刻度 |
| 定位分辨率 | 游标能移多细 | 1 纳秒步进 |
| 模型分辨率 | 模型实际按多细推进 | 模拟细步；ADC 采样周期 |
| 测量能力 | 实测的采样间隔、带宽、对齐不确定度 | 由仪器与设置决定，未知为空 |

把游标移到 1 纳秒，不会让 8 纳秒一次的 ADC 数据多出新的观测；曲线画得光滑，也不证明求解器有同样的精度。每条信号显示：原始采样间隔、模型有效范围、是否插值、是否摘要、时间基准、对齐不确定度。

**时间表示。** 事件时间用可配置的整数刻度（如皮秒）；周期性事件保留时钟域、计数、相位和频率定义。周期不能被刻度整除时，用相位累加器或有理数定义，避免每拍各自舍入后累计漂移。传给浏览器的大整数时间用字符串或大整数类型，绘图时再换算成相对当前视窗原点的小偏移。实测数据的跨时钟对齐带时钟映射、漂移和不确定度；达不到纳秒级对齐的，不在图上画成已知的纳秒先后。

**回放。**

- 不倒着积分。要看过去，先用已有迹线；需要完整内部状态时，从目标时刻之前最近的检查点恢复，再按原命令、原随机轨迹向前重放到目标时刻。
- 检查点内容即 5.5 节的快照内容，另加控制命令日志的位置、模型版本和配置校验值。
- 同一模型、同一离散化、同一配置、同一随机实现下，回放结果可复现：数字结果逐位一致；模拟量的浮点结果在固定环境下一致，并声明允许的数值容差。
- 把模拟步长改细，或把时间箱抽样改成单事件模型，是一条新的计算分支，不是把原轨迹"放大"，不承诺逐点相同。

**分支。** 视角、配色、曲线显隐不产生新运行。改变激光功率、PMT 增益、模拟响应、ADC 配置等，要么创建新分支，要么记录为带生效时刻的控制事件；旧标定是否仍适用要重新检查。历史结果不被覆写。

**查询返回状态。** 每次查询注明结果属于哪一种：原始记录、重放得到、插值、仅摘要、未记录。"精确恢复了这个离散模型的状态"与"物理上精确"是两回事，分开标注。

### 5.14 记录策略：检查点加按需重算〔V08、V20〕

**为什么不全量记录。** 20 路观察量、每路 4 字节、覆盖 9.6×10⁸ 个细步，未压缩约 76.8 GB。这只是一种假设记录策略下的量，但足以说明不能把整次运行的高频量全部存下来再塞给浏览器。

**默认策略。** 把高频模拟内部量当作可重算的派生数据，而不是要保存的数据。

| 数据 | 默认做法 |
|---|---|
| ADC 原始码流与完整性信息 | 全程记录，保留源样本身份 |
| 数字与控制事件 | 按事件精确记录，不展开成每纳秒一条状态 |
| 检查点 | 默认每行一个；在配置变化、阶段切换、异常附近加密 |
| 高速模拟内部量 | 默认不落盘；查看时从最近的检查点重放所需窗口 |
| 选定探针的多层摘要 | 全程记录最小值、最大值、首值、末值、计数，供总览使用 |
| 低速机械与漂移状态 | 按自身变化尺度记录，带插值策略 |
| 整帧图像 | 分块、多层，按视口加载 |
| 单光电子事件 | 只在短窗的 `event` 模式记录 |

**重放代价的量级。** 一行 7000 像素、每像素 16 个细步，共约 11.2 万细步。按旧模型的单步耗时外推：固定带宽约 38 毫秒，电流相关带宽约 220 毫秒。这是外推，V5 模型未实测；它说明"每行一个检查点"时，冷重放一个窗口的等待大致在可交互的范围内。检查点间隔最终由实测的恢复代价和存储预算决定，不写死。

**这个策略成立的前提。** 重放必须逐位复现原轨迹。5.7 节的随机数设计（白噪声由"物理源标识 + 全局样本序号"派生，有色过程的状态存进检查点）就是为此准备的。任何破坏可复现性的改动，都会让这个策略失效，所以"分块与重放不改变结果"是一条硬性回归测试。

**摘要的规则。** 总览用最小值与最大值的包络，不用均值降采样，否则短脉冲、削顶、溢出会被抹掉。逻辑信号用跳变和持续区间表示，不做平滑。摘要只用于显示，不替代标定、重建和误差评价所用的原始数据。

**解耦。** 仿真可以高速向前算，界面按屏幕刷新率画；也可以停下计算只回看。后端不需要每出一个 ADC 码就推一条消息：进度低频推送，波形按当前窗口批量查询，大数组用二进制传输。迹线存储、探针数量、最长重放跨度进入预算器，与板端内存预算分开。

### 6.3 存储、网络、USB、其他外设

- **DDR**：512 MiB，接在 PS 侧。PL 采集的数据要经 PS / PL 数据路径才能写入，不是可随意加深的 PL 缓冲。板端内存预算与工作站内存预算分开。
- **网口**：千兆 PHY 的信号接在 PL。两条候选实现：PS 以太网经扩展接口在 PL 做接口转换；或 PL 侧 MAC。见到现有工程前不选定。
- **USB**：调试口通往串口 / 调试芯片；数据口为 USB 2.0。两个数据口外形不同但共用同一 PHY，不能算两路带宽。
- **其余外设**：显示、存储卡、按键等分三类——参与采集、占用资源、排除。默认只登记，不仿真。

### 6.4 ADC 模块需确认的内容

模块原理图、芯片速度等级、时钟源与分频、模拟输入路径与耦合方式、差分驱动与共模、数字电平转换、模块数据时钟与芯片数据时钟的关系、数据位顺序、溢出标志、配置接口与掉电 / 输出使能连线。丝印和连接器标签不足以确认其中任何一项。

## 7. 模块设计

### 7.0 可行性预算器 `budget`

不运行仿真，输出一页报告。每个结论标注它依赖多少"假设"参数。

- **几何自洽**：面数、转速、焦距、扫描角、扫描宽度、占空比、行频、光点速度、像素率、所需采样率。
- **光子**：各密度档每像素光电子数、散粒噪声限的密度噪声、达到目标噪声所需光电子数、阳极电流是否越限。
- **电信号**：前端输出经驱动映射后是否落在 ADC 量程内；量化步长对应的密度步长；带宽对应的拖尾量级。
- **数据通路**（采纳审查包算法）：
  ```text
  原始速率 = 采样率 × 通道数 × 每样本字节
  保留速率 = 原始速率 × 数字保留占空比 / 抽取比
  线上速率 = 保留速率 + 包头与元数据开销
  ```
  这三行只适用于"原样保留或简单抽取"的情形。抽取、滤波、聚合都会改变数据合同，此时预算用实际的输出项率、字宽、通道数、质量标志和包开销计算，不是把原始字节率除以抽取倍数了事〔P01〕。
- **采集模式〔P03〕**：配置中显式指定，三种模式判定规则不同。

  | 模式 | 判定 |
  |---|---|
  | `continuous` 连续 | 长期输入不得超过可保证的服务能力，再检查突发、停顿和裕量。双通道 125 MSPS 全保留为 500 MB/s，超过千兆链路 125 MB/s 的理论上限，这种情况加深缓冲解决不了 |
  | `finite_frame` 有限帧 | 采集期间的平均输入可以高于出口，但要逐级证明：峰值积压不超过可用容量、采集入口始终收得下、采集结束后能在允许时间内排空 |
  | `periodic_burst` 周期突发 | 按完整的"采集—排空"周期和最坏停顿验证 |

  空闲阶段没用掉的服务额度，不能累加成以后可用的容量。板端实际可用内存、各级局部缓冲容量、DMA 传输能力、主机服务能力、完成时限分开记录。缺实测量时，只输出带假设标签的场景结论。
- **板端内存**：原始帧、重建帧、双缓冲、浮点图并存时的占用，减去系统保留量。各级内存按实际字节计，包括标签、对齐、包头和缓冲管理开销〔P04〕。
- 行频等未知量默认为空。用户可输入"假设场景"，报告强制标注。

验证：与包 A、包 B、审查包三方的预算输出逐项一致。

### 7.1 底片 `scene`

靶标库（密度阶梯、连续楔、斜边、线对、网格、斜线、均匀场、缺陷），各带解析真值；外部浮点密度图，带物理尺寸；条带式超采样；片宽可小于光学窗口；可选颗粒与镜面 / 漫射分量。

底片密度 D 先转成透射率 T = 10^(−D)，之后所有光学计算都在透射率或光功率上进行〔P09〕。这是两套包已经一致坚持的做法，V4 用测试固定。

### 7.2 光源 `optics.source`

功率、波长、逐行波动、周期纹波、强度噪声谱、慢漂移；常亮或门控。参考光通道默认关闭。

### 7.3 扫描几何与时基 `optics.scan` + `timing`

- 光学拓扑分三级记录：已观察、候选解释、待实测。光学件以映射表和光斑表接入，不按照片虚构镜头。
- 转镜：面数、转速、转速波动、逐面角度误差、逐面塔差、逐面反射率。
- 映射：理想 f-theta、f·tan、多项式、实测表。
- 行同步：探测器位置与触发抖动；与 ADC 时钟异步。包 B 的"直接加位置抖动"保留为简化选项。
- 送片：步进保持、匀速、带纹波、带加减速；编码器。
- 时钟树：区分 ADC、PL、PS、网口各域及其复位关系；板上晶振频率不等于 ADC 采样率。

### 7.4 光斑与眩光 `optics.psf`

椭圆高斯核心光斑，随场变化；宽尾眩光；离焦；可导入刀口实测。光斑积分对透射率做，不对密度做；光斑核的归一化、损耗、边界和遮挡规则写明〔P09〕。宽尾眩光、环境杂散、导光体串扰是并列的候选机制，哪一个主导高密度平台待实测判别。

### 7.5 集光 `optics.collect`

位置相关效率表、有限集光角、环境杂散光、片外直通光漏入比例。透明板状件的具体功能为候选解释。

### 7.6 PMT `detector`

泊松 + Gamma 倍增；增益与高压的关系作为可选行为模型（不绑定到那个 DAC）；分压链下垂与恢复；暗计数与暗电流；硬限幅仅作告警阈值。

**快时间响应〔V06〕。** 电子渡越时间、上升时间、渡越时间分散是三个不同的量，且随管型和工作条件变化，不能因为"用了 PMT"就给一个统一的纳秒延迟。两套旧包只有一个渡越延迟加一个带宽极点，都是假设值。V5 把快时间响应做成可选层：未启用或参数无来源时，界面显示"未建模"或"假设"，不画看似精确的电子运动。没有建模倍增极时，不声称显示了管内电子轨迹。

### 7.7 PMT 到前端的电气路径 `afe.input`

表示管座、线缆、输入负载的等效网络，可用极点 / 阻抗或实测端到端传递函数。没有测量时只保留接口。新增的极点必须改善独立验证集，而不是只拟合训练波形。

### 7.8 模拟前端 `afe`

对数 / 线性可切换，极性可配置；对数静态（理想式、带一致性误差、实测查找表）与温漂；对数动态用电流域状态方程；二级主放与驱动映射（增益、偏置、压摆率、限幅）；直流 / 交流耦合；任意极零点抗混叠；电流与电压噪声谱。

量程描述分四处：对数板输出、二级主放输出、模块输入、芯片差分输入，不混用。

### 7.9 ADC 转换 `adc`

采样抖动、量程与共模、增益与失调误差、非线性表、热噪声、限幅标志；每像素多个样本；双通道，通道角色显式登记。

模块画像保存寄存器原始转储与解释后的生效配置；配置变更产生新时期；未读回的寄存器只能用假设预设。

### 7.10 ADC 输出链路 `adc_link`

转换与传输分开：先由模拟量得到转换样本，再按模式产生引脚上的数据。

功能级内容：输出格式（码制、并行 / 交织）、数据时钟捕获边沿、位映射、通道顺序、溢出标志对齐、流水线延迟（区分输出模式）、测试码（交替码、固定码、伪随机）。

负例应能被检出：错边沿、错位序、错通道、溢出标志未对齐、测试码未退出。但"能否检出"取决于激励和冗余，见 7.11 节的故障记录要求〔P07〕。例如两个通道输入相同激励时，通道交换在当前配置下不可判别，应如实报告并给出增强自检方式（如两通道使用不同测试码）。

不做：引脚级建立 / 保持裕量分析。

### 7.11 数字采集参考模型 `digital`

以包 B 的 RTL 为起点，用整数运算写位精确参考模型：行同步的同步与量化、行内计数、有效窗口、标签对齐、每像素样本合并、打包、缓冲、溢出与错误标志。用 cocotb 驱动 RTL 逐拍比对。

故障注入：缺行同步、多余行同步、复位中断、时钟频差、缓冲回绕、位翻转。

每项故障记录〔P07〕：发生位置、由谁检查、所需的激励或冗余、检查点、实机上可观测的标志、检测时延、盲区。两类情况要分清：

- 测试台知道自己注入了什么，这只属于离线验证，不能包装成实机运行期告警。
- 实机运行期只能依靠真实存在的冗余（计数、测试码、校验）发现故障。没有冗余的码流中，某些误码不可判别，报告"当前配置不可判别"。

校验码只保护它生成点之后的载荷一致性，不能证明 ADC 采样本身正确。

**板端合并的限制〔P01〕。** 板端"合并"分两种：无损封装（打包、加标签）和数值聚合（平均、抽取、滤波）。对数前端的 ADC 原始码，不得默认先做数值平均、再由上位机反对数，并把结果当作线性光强平均的等价实现——对数码的平均对应的是几何平均。若要在 PL 或 PS 提前线性化并合并，必须冻结查找表和数值格式，并补齐相应的资源与误差证据。

### 7.12 传输与缓存 `transport`

可配置的队列图：ADC 接收缓冲 → PL 侧缓冲 → DMA 环 → DDR 缓冲 → 传输队列 → 主机接收队列 → 落盘队列。实际没有的级从画像中删除。

每级记录容量、服务曲线、排队延迟、峰值、溢出次数、丢失样本区间。服务曲线可用假设分布或回放实测记录。ADC 不可反压，后级可反压。

**守恒检查〔P04〕。**

- 不做数据变换的队列，以同一种计量单位核对：入队数 = 出队数 + 主动舍弃数 + 故障丢失数 + 队列余额。
- 聚合、抽取、压缩、重采样前后的计量单位不同，两侧项数不能直接比较，各自记录。
- 完整性以源样本身份的覆盖为依据：哪些源样本已交付、哪些被明确舍弃、哪些落在故障区间，并检查重复。只看总数相等不算通过。
- 一帧"必须保留的样本集合"由实验计划和数字保留窗口定义。片外未保留的样本不算丢样故障。

溢出后默认不静默覆盖：记录缺失区间，帧标为不完整；重建可输出带掩膜的研究图，不得标为完整图。

粒度：离散事件的服务曲线，不做处理器指令级或 DDR 信号级仿真。

### 7.13 控制与运行状态 `control`

软件状态：未配置 → 已配置 → 稳定中 → 标定中 → 就绪 → 扫描中 → 排空中 → 完成；另有故障与中止。这是 V4 自己定义的仿真状态，不代表实机已有该协议。

扫描结束不等于最后一束光离开底片：还要推进前端尾响应、ADC 流水线、各级缓冲与落盘。

**完成条件〔P11〕。** 帧结束用"最后一个需交付的源样本标识"加可选的尾采样范围来定义；尾采样容差和最长推进窗口显式记录。同时满足以下三条才标为完成：目标样本已写入或已明确标为缺失；相关队列已排空；输出已完成提交。不要求连续物理状态严格归零。中止、断电、超时都输出可追溯的不完整状态。

**配置变更与时期〔P11〕。** 命令的请求时刻、生效时刻、读回确认时刻分开记录。样本在采样那一刻绑定当时生效的配置。配置改变后仍在流水线里的旧样本，保留原时期，或按明确规则标为无效；不能按上传时的配置重新标记。任一状态下的复位、改配置、停机，都产生新时期或明确的不完整标记。

### 7.14 实验时间线 `experiment`

预热 → 暗 → 白 → 标定靶 → 样片 → 复核，跨阶段保留状态、漂移轨迹与控制时期。同一份白参考在间隔较长或增益改变后应表现出可观测的失配。

### 7.15 标定 `calib`

| 标定项 | 允许的输入 | 输出与约束 |
|---|---|---|
| 暗 / 遮光 | 有时间记录的遮光扫描 | 暗值、分布、漂移 |
| 白场 | 无片或参考透射扫描 | 逐列、逐面辐射响应与不确定度 |
| 对数 / 密度查找表 | 有来源的阶梯片标称值，或电流 – 电压表 | 适用范围、外推策略、饱和区掩膜 |
| 延迟与动态 | 同向的上升沿与下降沿、已知刻线、同步电注入 | 固定延迟与响应参数分开估计 |
| 扫描向几何 | 已知刻线或网格 + 实测时序 | 映射估计及残差 |
| 送片向几何 | 斜线、网格或独立位移基准 | 偏移；对均匀场返回"不可辨识" |
| 逐面增益 | 均匀场 + 可恢复的镜面相位分组 | 增益与置信度；失锁时不得用真值镜面号补回 |

标定协议只调用硬件能力清单中声明支持的动作。

**延迟补偿的来源〔P02〕。** 重建使用的补偿量只来自标定对可观测扫描、电注入或有来源的参考数据的估计，不读取正向模型的延迟真参数。图像配准求得的整体偏移不自动归因为电路纯延迟。

### 7.16 重建 `recon`

以包 B 的独立重建命令为起点。流程：校验数据完整性 → 码值 → 撤销驱动映射 → 查找表反演 → 扣暗、白归一化 → 在线性域合并每像素样本 → 逐面校正 → 二维不规则重采样 → 密度 → 无效掩膜与质量标志。

"先线性化再合并"由测试固定。流式处理。按"将来直接用于上位机"的标准编写。完整二维重建默认放在上位机。

**默认参考路径〔P01〕。** 原始码保留并打包 → 上位机撤销驱动映射并线性化 → 按像素估计量的定义完成扣暗、归一化和有效加权合并 → 几何重采样 → 密度。不同白参考或增益条件下，归一化与加权的先后次序由像素估计量的定义决定，不能随意交换。

**无效原因分开标记〔P12〕。** 以下情况各有独立标志：扣暗后透射率非正、白参考无效、超出标定范围、饱和、缺样。不得无标记地把非正透射率夹成一个小正数再输出成高密度值——两套旧包都是这么做的（分别夹到 1e-8），V4 改掉。

**二维重采样〔P12〕。** 声明坐标来源、有效支持范围、权重和边界规则。缺口超出允许的支持范围时保持无效。用于展示的缺口填补是单独的可选产物，不混入定量图。

**随数据保存〔P12〕。** 输出单位、像素间距、掩膜、有效覆盖比例、算法版本、标定版本。

### 7.17 评价指标 `metrics`

密度（各阶梯偏差、标准差、线性度、可用范围、高密度平台值）；分辨率（斜边法 MTF，两个方向）；噪声（功率谱、信噪比随密度）；条带（逐面周期分量、行间抖动）；几何（网格点位置误差、行距、斜扫残余）；完整性（样本守恒、缺行、溢出、限幅、无效像素）；动态（阶跃后拖尾与恢复）；误差分解（完美标定与现实标定、有噪与无噪、有无延迟误差的差值）。

同时对"无模糊真值"和"光学参考"报告。

**评价规则〔P10、P12〕。**

- 所有指标在固定且公开的评价区域与掩膜下计算，同时报告有效像素比例。
- 误差分解报告均方误差、偏差、方差，以及各消融项之间的交互。不用几个 RMSE 相减来表示各成因的百分比——RMSE 不可加。
- 借助真值的配准只用于给出上界，单独标注，不计作正常重建的效果。可在实机独立标定得到的补偿结果另行报告。
- 密度与 MTF 标注工作密度或光强、扫描速度和所处的非线性工作条件。

### 7.18 实测接入与辨识 `ident` + `observation`

- 导入器强制填写：设备、测点、探头倍率、耦合方式、带宽限制、采样间隔、触发源与阈值、时间原点、会话、时期、是否同次同步。缺项的数据不能作为硬验收基准。
- 观测模型：示波器带宽、探头、采样对被测波形的影响。
- 辨识分步进行，一次只解一类参数。每次报告可辨识的参数组合、先验、相关性。
- 例如激光功率 × 集光效率 × PMT 增益，缺少独立测量时只报告组合增益，不把三个分量都标为"实测"。
- 拟合数据与验证数据分开。对同一现象无法区分的候选模型并列保留。

### 7.19 命令行、报告、界面

命令：`budget / check / run / sweep / calibrate / reconstruct / metrics / ident / compare / report / cosim / replay / serve`。`replay` 从检查点重放指定时间窗；`serve` 启动本地查询服务。`check` 执行硬件画像与配置的规则检查。

命令行、报告和交互工作台共用同一套配置、数据格式和查询接口〔V01〕。报告为自包含离线网页，强制显示证据状态与配置模式。工作台从数字最小闭环阶段开始建设，详见 7.20–7.22 节：二维信号链、统一时间轴、波形、样本追踪、来源标签为必做；三维视图和桌面安装包为后续可选。

### 7.20 观测、迹线、回放、因果 `telemetry` `trace` `replay` `causality`

**信号注册表〔V17〕。** 每条可显示的信号登记一次：

| 字段 | 内容 |
|---|---|
| 标识 | 信号、所属组件、端口 |
| 物理域 | 光学、模拟、数字、机械、控制 |
| 量与单位 | |
| 值类型 | 标量、向量、事件、逻辑、样本块 |
| 来源、可见性、得出方式 | 即 5.2 节的三个正交字段 |
| 参数证据 | 假设、手册、实测等 |
| 模型 | 模型标识与版本 |
| 时间 | 时钟域、时期、原始采样或步长策略、时间支持、对齐不确定度 |
| 显示与记录 | 插值策略、记录策略 |

"接口上可观测"与"参数有实测证据"是两件事：仿真出的 ADC 码流在接口意义上可观测，但不是实机测量；经实测标定的模型输出，也不能标成"测得"。

**只读探针〔V15〕。**

- 探针不改变模型输入和随机数轨迹。修改探针配置、打开研究视图、回看历史，都不影响仿真与重建结果。
- 研究视图导出的报告、截图、探针数据带"仅仿真真值"标签。界面状态保存后再导入，不能把真值字段变成标定输入。
- 两种视图：研究调试视图可看真值；实机可观测视图只显示实机接口上读得到的内容。

**迹线与事件索引。** 按 5.14 节的记录策略分块存储。查询时带目标像素宽度，由后端选择合适的摘要层，并在响应里说明取的是哪一层。

**回放。** 实现 5.13 节的检查点恢复与前向重放。重放窗口的结果只读发布，不写回原运行。

**因果。**

- 样本链路：给定一个样本，返回它的四个时间戳、经过的队列、所在数据块，以及最终落到哪些像素。
- 像素反查：给定一个像素，返回参与它的样本集合和重采样权重。权重由重建模块按需重算，不全程保存。
- 依赖窗口：线性环节返回响应核及截断误差；非线性环节返回已定义的依赖范围。

**查询接口〔V19〕。** 以下是建议规格，第二级工作台才需要服务端实现：运行清单、信号列表、指定时刻的组件状态、时间窗内的迹线（带像素宽度）、时间窗内的事件、样本链路、图像分块、请求重放窗口、创建分支、进度订阅。连续拖动时，旧查询可取消，或由前端按请求序号丢弃迟到的结果。已落盘的不可变数据可以缓存；仍在生成的时间范围带版本或进度边界。

### 7.21 工作台界面 `ui`

**布局〔V09〕。** 二维工程图为主，虚拟示波器常驻，底部是多尺度时间轴。

```text
┌──────────────────────────────────────────────────────────────┐
│ 实验 / 运行 / 时期 / 模型等级 / 证据状态 / 数据完整性          │
├──────────┬───────────────────────────────┬───────────────────┤
│ 组件树   │ 光路与器件视图                │ 当前组件探针      │
│ 光学链   │ 激光 → 扫描 → 底片 → 集光     │ 数值、单位、来源  │
│ 模拟链   │                   ↓ PMT       │ 状态、适用范围    │
│ 数字链   │ 前端 → ADC → FPGA → 缓冲      ├───────────────────┤
│ 图像     ├───────────────────────────────┤ 样本因果追踪      │
│ 事件     │ 虚拟示波器 / 数字逻辑波形     │ 采样 → 输出 → 接收│
│          │ 光功率、电流、电压、码字      │ 缓存 → 主机 → 像素│
│          │ 时钟、行同步、有效窗、溢出    │                   │
├──────────┴───────────────────────────────┴───────────────────┤
│ 实验总览 → 帧 → 行 → 像素 → ADC 拍 → 纳秒事件                 │
│ 播放 / 暂停 / 单步 / 精确跳转 / 缩放 / 事件定位 / A-B 游标     │
└──────────────────────────────────────────────────────────────┘
```

只有一个仿真时间游标。光路、数值、波形、图像、样本追踪都由同一组"运行 + 时期 + 游标时间"驱动。浏览器的刷新时钟只决定何时画下一帧，不是物理过程的时间来源。二维视图讲清连接关系，波形视图支持工程判断，三维视图（可选）讲清空间位置；三者共用组件与信号标识，不各自维护数据。

**各层显示什么、避免什么误导。**

| 层 | 显示 | 点击后 | 必须避免 |
|---|---|---|---|
| 激光与光路 | 光源、路径、扫描方向、光斑位置 | 功率、波长、路径来源、传播模型 | 把示意光线当成逐光子轨迹 |
| 扫描光学 | 转镜姿态、当前面、扫描窗口 | 角度定义、映射、面相位的来源 | 从示意图的像素距离反推光程 |
| 底片 | 密度或透射率、片夹、片外区、已扫位置 | 被照区域、积分权重、四种窗口状态 | 把输出裁剪等同于光学遮挡 |
| PMT | 入射功率、光电子统计、电流与恢复 | 量子效率、增益、噪声、快响应参数及来源 | 未建模时声称画出管内电子轨迹 |
| 模拟链 | 电流到电压、对数压缩、滤波、限幅、基线 | 每个真实定义的测点的输入输出 | 混淆对数板、主放、模块输入、芯片差分输入 |
| ADC | 采样点、保持值、量化码、流水线 | 当前采样序号与当前输出序号 | 让一个样本在采样瞬间就出现在 FPGA |
| FPGA | 接收拍、位映射、行同步、有效信号 | 时钟域、标签、失步与位序错误 | 把功能时序当成建立与保持裕量验证 |
| 数据通路 | 队列占用、积压、传输与落盘状态 | 容量、服务、丢样区间、守恒账本 | 把网络到达时间当成曝光时间 |
| 成像 | 已形成的图像、质量掩膜、当前扫描行 | 该像素对应的样本集合与权重 | 暗示一个像素只对应一个样本 |

状态除了颜色还要有文字或图形，不只靠红绿区分。非关键探针默认隐藏。

**时间轴。** 三层：总览（预热、暗、白、标定、样片、复核、排空各阶段）、帧与行、细层（像素覆盖、模拟响应、ADC 采样与输出、FPGA 接收拍）。

- 操作：播放与暂停；按 1 纳秒或自定步长前后移动；上一个或下一个 ADC 采样、行、异常事件；直接输入时间或样本序号；缩放到选区；A/B 游标与时间差；从像素跳到相关样本和时间范围。
- 播放速度写成"每现实秒推进多少仿真时间"，例如每秒 100 纳秒，不只写一个倍率。
- 暂停冻结一切与仿真过程有关的动画；相机旋转、鼠标悬停可以继续。
- 拖到未计算的区间显示"未计算"；只有摘要的显示"摘要"；正在重放的显示重放状态。不用随意生成的动画填补。

**外观与物理拓扑分开〔V16〕。** 每个组件有稳定的标识，但外观姿态、物理参数、端口、状态字段、证据各自记录。在图上挪动一个方框只改布局；改变真实镜头位置是物理配置变更，产生新的运行或时期。

**三级交付。**

| 级别 | 形态 | 依赖 | 适用 |
|---|---|---|---|
| 第一级 | 每次运行生成的自包含离线网页，数据内嵌，原生 SVG 与 Canvas | 无服务、无外部依赖 | 数字最小闭环与小算例；沿用包 B 观察器的做法 |
| 第二级 | 本地 Python 服务加浏览器前端，按窗口查询，支持重放与分支 | 查询接口、迹线存储 | 整幅运行、任意时刻定位 |
| 第三级 | 三维空间视图、布局保存、桌面封装 | 第二级稳定 | 可选 |

第一级网页内嵌的数据量有限，只能覆盖短片段或单行，这是它的边界，不是缺陷。第二级的前端框架到时再选，由将来维护它的人决定；波形用 Canvas 或 WebGL 专用视图，不把高频点画成大量页面元素。

### 7.22 候选技术〔V21〕

| 层 | 候选 | 取舍 |
|---|---|---|
| 二维连接关系 | SVG；规模大了可用节点图库 | 第一级用原生 SVG |
| 波形与时序 | Canvas 或 WebGL | 必做 |
| 本地服务 | FastAPI 加 WebSocket 进度通道 | 第二级；仿真计算与服务事件循环分开进程 |

| 跨语言大数组 | Arrow | 可选，只是交换格式 |
| 外部调试导出 | Perfetto 事件轨迹；RTL 保留原生波形文件 | 可选 |

这些是候选，不是都要引入。选型不得反过来要求重写物理模型。

### 8.2 两通道示波器下的做法

三路同次采集需要四通道示波器，或带数字通道且模拟通道够用的设备。继续用现有两通道时：通道 1 固定接已确认的行同步信号，通道 2 依次接一个模拟节点，重复扫描。数据必须标为"非同次采集"，只有稳定性检验通过后才做统计比较，不能当作逐点同步的三路观测。

### 9.2 可观测性的两类测试〔P05〕

两类测试目的相反，必须分开，不能互相替代。

| 测试 | 固定什么 | 改动什么 | 期望 |
|---|---|---|---|
| 隔离测试 | 原始码流、可观测事件、标定文件、算法版本 | 只扰动评价侧私有的真值元数据（真值镜面号、真实坐标、真实功率的记录），然后重放标定与重建 | 结果不受影响 |
| 物理敏感性测试 | 配置与算法 | 在规定的不饱和场景中改变正向模型的光强或坐标，并**重新生成观测** | 重建结果按模型发生相应变化 |

- 隔离测试中，运行标定与重建的进程不得拥有真值目录或真值内存对象的读权限。
- 不得要求"物理量变了、重新采到的数据也变了，而重建仍然不变"。
- 一个输出恒定值的重建能通过隔离测试，所以隔离测试必须与物理敏感性测试配对。

V4.0 原来写的"改动真值镜面号、坐标、功率，重建不变"没有说明是否重新生成观测，按字面理解会与物理矛盾，已按上表改正。

### 9.3 阈值来源

单位、类型、引脚冲突、样本计数、位精确比对可以设严格规则。物理残差、密度精度、MTF、扫描时间、几何容差需要产品指标和测量不确定度支持；未确定的阈值不为凑验收临时填数。

## 10. 开发阶段

每个阶段以门槛通过为准。人周为量级估算；括号里先写 V5.0 的数字，再写 V4.1 的原数字。工作台部分需要前端技能，是否由同一人完成待定。

### 阶段 0：证据、硬件画像、基线冻结、观测合同（2.5–4 人周；原 2–3）

- 两套包冻结进 `legacy/`，纳入版本管理；合并三张参数证据表（包 A、包 B、审查包）。
- 导入并复核审查包的引脚表、硬件配置草案、需求表、规则测试。
- 安装 Icarus 与 ngspice，实际执行两套包的 RTL 测试台和网表，结果无论通过与否都记录。
- 两套包逐环节交叉比对，写差异说明。
- 补齐重跑证据〔P10〕：代码版本、输入与配置校验值、随机种子、运行命令、环境、原始日志、判据，全部入库；配准消融与单步耗时的脚本入库，并定义固定的评价区域与掩膜。
- 原始码流格式与包边界草案。
- 冻结观测合同〔V22 的 M0〕：组件与信号注册表、时间与样本身份、来源字段、查询返回状态。迹线存储做一次小基准后定型。
- **门槛**：所有未知项登记为空值；不虚构 ADC 到板端的接线；回归基线可一键重跑；界面骨架上，未知数据不显示成零或测量值。

### 阶段 1：可行性预算器（1–1.5 人周）

- 实现 7.0 与 `check` 命令。
- **门槛**：与三方已有预算数字一致；硬件模式下缺项即拒绝。

### 阶段 2：数字最小闭环与第一级工作台（5–7 人周；原 3–4）

- 从 ADC 测试码出发，贯通输出链路、接收、标签、缓冲、多级队列、原始文件、完整性检查、最简重建。
- 位精确参考模型与 RTL 协同测试台；故障样例；码流格式定稿。
- 第一级工作台〔M1〕：ADC 与逻辑波形、统一时间游标、样本追踪（四个时间戳）、丢样轨道、来源标签。
- **门槛**：参考模型与 RTL 逐位一致；每个丢失样本可追溯；样本守恒成立；没有真值经元数据泄漏；界面上延迟只计一次，能从一个码字定位到它的采样时刻和出错层级。

### 阶段 3：合并基线物理模型接入、回放与第二级工作台（7–9 人周；原 4–5）

- 按第 3 节的取舍合并两套模型，以理想级与行为级子模型接入。
- 连续状态接口、四窗口、实验时间线、分层随机数。
- **门槛**（两套，分开判定〔P06〕）：
  - 旧行为：`legacy_a`、`legacy_b` 预设复现包 A、包 B 旧结果，并在报告中标出它们已知的限制（按行重置状态、用真参数重建、`MODEL` 标定）。
  - 新模型：`v4_nominal` 预设下，分块不产生假条带；片外、跨行、跨标定阶段的历史不丢失。修复旧缺陷后指标允许变化，附差异说明。
  - 性能场景（含标定阶段、片外模拟、读写、双通道）跑通并记录耗时与内存。
- 物理纵向切片〔M2〕：密度边缘 → 光功率 → PMT → 前端 → ADC，在二维光路、探针、同步波形中显示。
- 历史回放〔M3〕：检查点、前向重放、迹线与摘要、查询接口；第二级工作台的任意定位、缩放、未记录状态。
- **工作台门槛**：所有视图来自同一条真实运行轨迹，不是预设动画；反复拖动不改变既有结果；没有记录的细节不被伪造；观察无扰动测试通过；实测检查点大小与单窗口重放耗时并记录。

### 阶段 4：标定、重建、指标、成像视图（4.5–6 人周；原 3–4）

- 实现 7.15–7.17，标定文件三种状态与适用性检查。
- **门槛**：注入已知延迟、逐面误差、畸变、对数误差后能恢复；不可辨识问题正确报告；对包 B 的参考算例，在固定评价区域与掩膜下给出均方误差、偏差、方差和消融交互，把对齐误差与其他误差源分离开，并区分"真值辅助配准的上界"与"可独立标定得到的补偿"〔P10〕。
- 成像与对比〔M4〕：图像与质量掩膜视图、像素反查、两次运行的并排对比。**门槛**：研究真值不进入标定与重建；标定与配置不匹配时界面可见。

### 阶段 5：正向模型增强（4–5 人周）

- **门槛**：每个子模型有解析或交叉验证测试；每加一个机制，用阶段 4 的指标量出它对图像的影响。没有对应测量手段的机制只留接口。

### 阶段 6：板级验证、实测辨识、实测叠加（4–5.5 人周，依赖资料；原 3–4）

- 设备关联〔M5〕：导入实际配置与测量波形，带对齐不确定度；实测叠加、残差、受限的实机可观测视图。

### 阶段 7：性能、三维与产品化（4–6 人周，可选；原 2–3）

## 11. 风险

| 风险 | 应对 |
|---|---|
| 关键原理图长期拿不到 | 阶段 0 即请求；对数板与载板为自研板；准备只靠输入输出测量的黑箱路线；研究模式不受阻 |
| 范围膨胀：硬件画像、队列、控制、观测模型都加进来后，仿真软件变成板卡设计验证平台 | 每块都限定粒度（第 4.2 节与各模块"不做"）；硬件部分只做规则检查与服务曲线 |
| 合并两套实现时引入隐蔽差异 | 两个兼容预设 + 差异说明 |
| 模型细到无法被实测约束 | 每个机制对应一项测量；辨识报告可辨识组合 |
| 顺序推进后性能不达标 | 目前只有由旧模型单步耗时外推的量级（固定带宽约 5.5 分钟、电流相关带宽约 0.5 小时），整幅未执行；阶段 3 用专门的性能场景实测；`fast` 模式兜底；线性环节可解析推进 |
| 板端过早做数值聚合，造成不可逆的定量误差 | 默认原始码保留；板端聚合必须先冻结查找表与数值格式并给出误差证据 |
| 数字参考模型与 FPGA 各自演化 | 码流格式与参考模型为单一规格 |
| 仿真数字被当作实机性能 | 报告强制显示证据状态与配置模式 |
| 工作台把项目重心从物理正确性拉向界面效果 | 界面不得生成与后端状态无关的动画；每级工作台的门槛都以"数据来自真实运行轨迹"为准；三维放在最后且可选 |
| 画面的精细程度超过模型的可信程度 | 四种时间精度、插值与摘要标记、未建模标记强制显示 |
| 按需重算的回放不可复现 | 分块与重放一致性作为硬性回归；数字结果逐位比对 |
| 重放一个窗口太慢，拖动不流畅 | 目前只有外推量级；阶段 3 实测后调整检查点间隔，或对选定探针改为落盘 |
| 研究探针成为真值泄漏通道 | 独立数据路径与接口白名单；导出带标签；隔离测试覆盖界面导出 |
| 前端技能缺口与工期 | 第一级用原生网页技术，不引入框架；第二级启动前重新做工作分解 |

## 14. 建议的第一步

5. 冻结观测合同（信号注册表、时间与样本身份、来源字段），并用数字最小闭环的测试码数据做出第一级工作台的最小版本：一条时间轴、ADC 与逻辑波形、一个样本的四个时间戳。
