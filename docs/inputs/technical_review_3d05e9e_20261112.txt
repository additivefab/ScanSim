## 结论：值得继续开发，但还不能用它直接证明便携扫描仪的性能

**ScanSim 已经具备一个有价值的仿真软件框架：它不是简单的光路动画，而是覆盖了光电模型、数字采集、数据完整性、标定、重建和时间回放的研究平台。我的建议是保留这个框架继续开发，不必推倒重来。**

但是，针对我们现在的两个核心任务——**诊断积分筒亮线、设计 80 mm 连续便携式扫描仪**——它目前仍有重要缺口。我尤其发现了两项应优先处理的问题：

**第一，低光随机电流在没有固定物理输入响应的情况下直接进入对数运算，计算结果可能随仿真时间步改变。第二，示范 RTL 的样本计数器只有 32 位，直接用于长片连续采集会发生回绕。**

此外，当前扫描运动仍是多面转镜模型，积分筒仍是简化的收光效率函数，不能只修改扫描宽度，就认为已经完成了上一版便携振镜方案的仿真。

# 二、哪些设计做得好，应该保留

## 1. 在透射率域模拟光学，而不是直接模糊密度

`truth/scene` 先将光学密度转换为：

\[
T=10^{-D}
\]

场景插值和光斑积分都在透射率域进行。`truth/psf` 使用高斯光斑加权取样，而不是把密度图直接高斯模糊。

这与我们之前确定的物理链路一致：**光斑覆盖范围内被平均的是透射光，不是密度数值。**这一点是应该保留的正确基础。 

## 2. 重建不依赖仿真器内部“真值”

`recon/density.py` 的路径是：

```text
ADC 原始码
→ 标定查找表转换到线性信号
→ 线性域暗参考、白参考校正
→ 按空间位置进行加权累积
→ 透射率转换为密度
```

同时保留无效原因、支持权重和 NaN，而不是把所有缺失区域自动填成一张看似完整的图。

**这是非常重要的架构优点。**否则仿真可能在重建时悄悄使用真实坐标、真实收光效率或真实底片密度，得到实机根本无法复制的结果。当前代码已经在主动避免这种问题。

## 3. 随机数、分块和回放的设计比较扎实

物理链采用绝对细步索引驱动；随机数按种子、来源、时钟域和绝对位置生成。模拟状态跨行保留，检查点记录前端状态和配置哈希。

测试中有分块一致性、检查点恢复、探针不干扰、相同种子可重复等检查。这些能力对长片仿真和故障回放很有价值。  

但要注意一个区别：

> **分块一致，说明同一套计算规则具有可重复性；不说明这套规则已经正确代表真实硬件。**

下面的随机对数问题就是一个例子：模型可以非常稳定、逐位可重复地计算出一个具有物理偏差的结果。

## 4. 原始数据完整性没有被忽略

ZLRAW 草案包含会话、时期、样本序号、通道、块序号、CRC 和缺失处理规则，也明确指出 CRC 不能证明 ADC 采样本身正确。

这比只输出一个无头二进制图像文件更适合我们后续做实机采集。不过，文档同样明确说它还是**待与 FPGA 侧共同冻结的草案**，不能默认原机已经按这个格式输出。

# 三、最重要的问题：随机光电流直接进入对数，导致时间步影响结果

**优先级：P0——在修正或限定适用范围前，不建议用当前带噪物理链判断高密度测量能力。**

## 1. 源码实际做了什么

当前 PMT 模型每个细时间步计算：

\[
N\sim\operatorname{Poisson}(\lambda\Delta t)
\]

再通过倍增模型得到电荷 \(Q\)，并换算为：

\[
I=\frac{Q}{\Delta t}
\]

随后 `Afe.process()` 先执行：

\[
V=V_0+sS\log_{10}
\left(
\frac{\max(I,I_{\mathrm{floor}})}{I_{\mathrm{ref}}}
\right)
\]

**取完对数之后，才执行前端低通和抗混叠滤波。**当前整链并没有先实现一个固定物理时间响应来形成 PMT 输出电流波形；配置 PMT 带宽极点时，`Chain` 会直接抛出 `NotImplementedError`。  

## 2. 为什么这会有问题

缩小 \(\Delta t\) 时，每个时间格内的平均光电子数减少，出现零光电子的概率增大。

零电流又会被 `I_floor` 截住，再进入对数。所以：

\[
E[\log I]\ne \log E[I]
\]

而且这里的差值会随着**数值时间格的宽度**改变。

如果没有固定的探测器脉冲响应或输入电路响应，细化仿真时间步就可能等效于改变了对数环节所看到的电流统计，而不只是提高计算精度。

## 3. 我做的独立数值复核

为隔离这个问题，我按源码公式选取以下测试条件：

初级光电子率 \(10^8/\mathrm{s}\)、PMT 增益 1000、倍增额外噪声因子取 1、暗电流为 0、对数电流下限 1 pA、斜率 \(+0.25\ \mathrm{V/dec}\)，ADC 采样率固定为 1 MHz。

这里使用的是**精确泊松概率求和**，不是运行整个 ScanSim，也不是实机测量。平均阳极电流在各组中保持不变，约为 16.02 nA。

| 模拟过采样倍数 `os` | 细时间步 | 每步平均光电子数 | 平均对数输出相对“对平均电流取对数”的电压偏差 |
|---:|---:|---:|---:|
| 4 | 250 ns | 25 | −2.25 mV |
| 8 | 125 ns | 12.5 | −4.69 mV |
| 16 | 62.5 ns | 6.25 | −11.73 mV |
| 32 | 31.25 ns | 3.125 | −56.46 mV |

**只改数值时间步，平均输出就发生了明显变化。**计算脚本和完整结果在下载包中。

这不是说真实前端一定应该输出 \(\log E[I]\)，也不是说这些数值就是最终密度误差。真实对数电路确实是非线性的，标定也可能吸收部分直流偏差。问题在于：**物理输入响应不能由任意选择的仿真步长替代。**

## 4. 为什么已有测试没有发现它

当前整链细步收敛测试，明确将 `shot_noise` 设为 `False`。

这个测试可以验证确定性波形的数值收敛，但没有验证“散粒噪声＋对数非线性”的统计收敛。PMT 单独的均值、方差测试，也不能替代整条非线性链路的测试。

### 建议修复方法

先根据实际 PMT 与前端拓扑，定义固定物理时间响应，例如光电子电流脉冲、探测器输出响应或前端输入节点动态；然后再进入相应的非线性环节。

验收时固定光功率、真实带宽和 ADC 时钟，只改变数值时间步，比较**稳态均值、带宽内噪声、功率谱、低光阶跃及独立标定残差**。随机模型应检查统计量收敛，不要求不同时间网格下随机波形逐位相同。

# 四、连续扫描的阻断项：示范 RTL 样本计数器只有 32 位

**优先级：P0——针对把该 RTL 用于长片实机采集。**

`cosim/rtl/scanner_capture.sv` 中：

```verilog
reg [31:0] sample_count;
output reg [31:0] sample_out;
```

`sample_count` 每个采样时钟递增，而不是只在有效像素窗口递增。

因此，在我们之前讨论的 20 MSPS 工作点下：

\[
t_{\mathrm{wrap}}=\frac{2^{32}}{20\times10^6}
=214.7483648\ \mathrm{s}
\]

按照便携版候选送片速度 2.5 mm/s，对应：

\[
L_{\mathrm{wrap}}\approx536.87\ \mathrm{mm}
\]

**也就是说，不到 0.54 米，计数器就回绕了；而标准模式扫描 1 米需要 400 秒。**

必须准确区分：**这是示范 RTL 的问题，不是说 Python 整条链或 ZLRAW 都只有 32 位样本序号。**ZLRAW 的 `first_sample_index` 已经定义为 64 位。真正的风险是将来两者接起来时没有明确高位扩展、回绕或时期规则。

建议统一为 64 位全局样本计数，或者制定严格的高位扩展协议，并测试回绕附近的丢包、复位、重连和行同步。测试平台可以从接近最大值处启动，不必真的仿真几分钟才检查一次边界。

# 五、另外几个会直接影响我们判断的模型问题

## 1. 窗外光斑坐标被夹在底片边缘

`truth/scan` 先将扫描归一化坐标限制到 `[0,1]`：

```python
u = np.clip((tau - ta) / cfg.active_s, 0, 1)
```

然后用这个 `u` 计算实际 `x`。而场景又把 `x=0` 和 `x=width` 作为片内位置。

因此，在**激光不关断、点光斑**的场景中，有效窗口之前和之后，光斑会“停在片边”，而不是沿轨迹继续走到片外。 

按演示几何计算，窗口开始前 100 μs，未夹紧的线性横向坐标应为约 −12.57 mm，当前公式给出 0 mm。若底片密度为 3.0 D、片外透射率为 1，两个位置对应的透射率相差 1000 倍。

这是特定条件下的模型反例，不代表所有默认运行都错；默认窗口外关光时影响可能被隐藏。但我们之前很关心**片外强光造成的前端恢复和行头拖尾**，这个问题恰好会干扰该分析。

**建议将物理轨迹、光学口径、激光门、底片边界、数字保留窗口和输出裁剪彻底分开。**物理坐标不应为了方便画图而夹紧。

## 2. 当前不是单轴闭环振镜模型

目前源码采用：

\[
f_{\mathrm{line}}=\frac{N_{\mathrm{facet}}\cdot rpm}{60}
\]

\[
v_x=2f\omega,\qquad v_y=p_yf_{\mathrm{line}}
\]

并加入三次畸变、逐面偏移、逐面增益和行起点抖动。这适合现有多面镜方案的简化研究，但没有振镜指令角、实际角、伺服动态、回程和稳定区。

**把 `facets` 改成 1，并不等于实现了单轴振镜。**

如果便携机最终仍选多面镜，当前模型可以保留；若采用上一版建议的单轴振镜，应新增独立的运动模型，共用后面的光电链和重建链。

纵向也应拆成：

```text
真实底片位置 → 编码器观测 → 重建采用的位置估计
```

这样才能研究打滑、轮径误差、偏心、张力变化和编码器丢脉冲，而不是始终用理想匀速送片替代实际运动。

## 3. 积分筒模型还不能解释局部涂层亮线

当前收光模型只有：

\[
\eta(u)=\eta_{\mathrm{pre}}\eta_{\mathrm{collect}}
\left[1-r(2u-1)^2\right]
\]

再加一个常数杂散光功率。它可以表示缓慢的边缘衰减，但不能表示局部涂层缺陷、接缝、侧窗特殊路径、角度敏感性或实测收光曲线。源码也明确标注“没有实测表”。

针对我们目前的问题，优先级最高的不是立刻做复杂三维光线追迹，而是加入：

\[
\eta=\eta(x,\theta)
\]

以及测量条件、位置采样间距、光源归一化方法和不确定度。

随后分别测试：局部效率峰谷、标定与扫描的位置错配、入射角改变、响应漂移。**不能用同一条精确响应曲线制造条纹，再用它的精确倒数校正，然后据此证明真实机器一定能消除亮线。**

## 4. PMT 超限标志不是饱和模型

`anode_limit_a` 目前只是比较电流是否超过阈值，然后置一个标志。超过限制后，电流本身仍按原公式继续计算，没有增益压缩、空间电荷效应或恢复过程。

因此它可以用于提示“这个工作点值得警惕”，但不能用于预测饱和后的波形，更不能证明对数放大器已经解决了 PMT 的动态范围问题。

此外，前端和 ADC 仍是简化模型：前端缺少实际传递误差、温漂和交流耦合，ADC 缺少输入噪声、增益偏置误差和非线性等项。 

## 5. 双通道的公共随机量和独立噪声需要分开

这是一个条件性问题，不是默认双通道必然错误。

当前命令行给第二通道使用不同种子，默认零行抖动场景可以工作；但打开行起点抖动后，流式引擎要求两通道使用相同种子，以保证扫描时序一致。

与此同时，PMT 随机数也使用种子、来源、时钟域和步号生成，没有独立探测通道键。相同种子和配置就会共享相同的 PMT 随机数。  

建议按真实物理关系划分随机来源：

**公共扫描运动、公共激光波动、各通道独立探测噪声、各通道电子噪声，以及公共和独立的时钟分量。**

否则，信号／参考比值可能得到不真实的噪声抵消，或者两个本来应共享运动的通道反而不同步。

# 六、“流式运行”还不等于“长度不限”

目前 `stream_physical()` 的好处是：**采集载荷按行生成和写入，不必把整幅 ADC 数组一次性留在内存。**

但函数仍要求预先给出 `lines`，并在正式生成载荷前建立整次扫描的：

```text
同步时刻列表
→ 采集窗口列表
→ 传输项目列表
→ 队列模拟结果
→ 已交付项目集合
```

因此，元数据仍随总行数增长，尚不是未知终点、长期在线、内存有界的扫描器实现。仓库性能报告也主动承认这一点。 

对于我们的长卷设备，我建议下一步改成**逐块产生事件、逐块推进队列、逐块写索引**，并加入磁盘满、断网、中途结束、异常掉电和恢复扫描测试。

这里的目标不是数学上的无限长，而是：

> **扫描开始时不需要知道最终长度；扫描进行多久，内存占用也不会随全部历史无限增长。**

# 七、怎样理解“845 项测试通过”和大幅面结果

## 1. 845 项测试是积极证据，但不是实机性能证书

开发记录报告：2026 年 11 月 12 日全量测试 **845 项通过**，耗时约 68.84 秒，环境中包含 Icarus，并且 Ruff 检查通过。

**这是仓库已有的运行记录，本次我没有复跑这 845 项。**

我看到的测试确实覆盖了不少有价值的行为，不能把它们贬成“都是空测试”。但测试能证明什么，取决于断言内容。比如无噪声细步收敛，不能证明带噪对数链收敛；短时 RTL 窗口正确，也不能证明长片样本计数不会回绕。

## 2. 当前 `nominal` 不是 50 μm 便携机预设

`nominal_config()` 基本沿用 `demo_config()`：

| 参数 | 当前研究预设 |
|---|---:|
| 横向宽度 | 80 mm |
| 横向列数 | 40 |
| 采样网格 | **2 mm** |
| ADC 采样率 | 1 MSPS |
| 光斑 FWHM | **1.5 mm** |
| 扫描器 | 4 面、6000 rpm 的多面镜模型 |

所有这些数值被标为假设。

所以：

**“预设宽度也是 80 mm”不代表它已经验证了“80 mm、1600 列、50 μm”的便携设备。**

1 MSPS 研究预设本身并不是错误；错误会发生在把这个通用研究算例当成真实 AD9268 板卡工作点时。

## 3. 大幅面结果主要证明了数据路径能承载较大任务

仓库报告给出了以下结果：

| 规模 | 采样率 | 端到端耗时 | 峰值内存 |
|---|---:|---:|---:|
| 4000 × 5000 | 50 MSPS | 1277.5 s | 404.1 MB |
| 7000 × 8600 | 20 MSPS | 1108.2 s | 247.1 MB |

但报告同时说明：**散粒噪声关闭、光斑积分为 3×3、两个任务并发运行，且都超过了 900 秒工程目标。**因此不能把这张表当作当前完整带噪模型的性能排名，也不能从“模拟零丢包”推出真实硬件零丢包。

同一报告中的约 **0.00026 OD**，是大幅面阶梯平台跨行统计得到的误差，不是高密度区域逐像素噪声，更不是实机密度准确度。

而 `nominal` 的 0.04343 OD、0.02770 OD 两种 RMSE，分别针对不同参考图；旧包的更低 RMSE 又来自不同理想算例。**这些数字不能混成一张“谁更准确”的排行榜。**

# 八、标定方向正确，但还缺真实测量闭环

当前对数标定拟合的是：

\[
\mathrm{code}=a+b\log_{10}(T+d)
\]

它利用暗场、白场和已知密度阶梯估计参数，然后生成 257 个查找表节点。这个流程比直接使用仿真内部参数反演更有价值。

但要注意：**257 个节点是拟合模型生成的，不是 257 个独立实测点。**当前拟合仍假定了特定形式的对数传递关系，并不自动覆盖真实前端的任意非线性。

后续应支持两种标定来源：

**参数化电路模型拟合**，适合解释和约束已知电路；**带不确定度的实测单调传递表**，适合修正真实器件偏差。

目前 `ident` 虽然出现在命令帮助中，但尚未接入执行处理器，运行会提示未实现。不能把它理解为已经具有实测参数辨识能力。

另一方面，仓库现在已经增加了 AD9268 V4.1 模块资料清单及相关设计资料。**不能继续简单沿用之前“完全没有模块资料”的判断。**不过，新增载板工程的记录也明确写着电路正文尚未解码，结构元数据不等于电气网表或接线验证。

# 九、软件可用性和交付方面的具体问题

| 项目 | 当前情况 | 建议 |
|---|---|---|
| 自定义整机参数 | 主 `run` 命令只有 `demo/nominal` 预设，没有通用 `--config` | 统一版本化配置；预算、运行、回放使用同一份配置 |

# 十、怎样把它改成真正服务于 ZL80 的工具

我建议保持现有分层，只新增或替换关键模块。

## 1. 建立独立的 ZL80 配置，而不是覆盖演示预设

把原 `demo/nominal` 留给快速测试，新增便携机研究配置，明确区分：

**实测值、厂家资料值、设计目标、暂定假设。**

尤其不要把上一版方案中的 135 mm 焦距、80% 前向占空比、光子预算和 PMT 增益直接标成已确认硬件参数。

还要统一光斑定义：现有代码用 **FWHM**，上一版设计目标用 **1/e² 直径**。对高斯光斑，两者满足：

\[
d_{\mathrm{FWHM}}
=
\sqrt{\frac{\ln2}{2}}\ d_{1/e^2}
\approx0.5887d_{1/e^2}
\]

所以 35 μm 的 1/e² 直径约对应 20.6 μm FWHM，不能直接在配置中填成 35 μm FWHM。现有 PSF 字段确实采用 FWHM。

## 2. 把运动模型做成可替换接口

建议支持两条路线：

```text
polygon：保留现机多面转镜研究
galvo：增加指令、实际角度、回程和稳定窗口
```

两者都输出物理位置和时间，但重建端只使用硬件能够提供的同步、反馈和标定信息，继续保持当前的真值隔离原则。

## 3. 先接入实测积分筒曲线，再决定是否做完整光线追迹

最先实现的位置响应表就能帮助回答：

**现有亮线的幅度能否由实测收光异常解释？标定错位多少会留下可见条纹？换内胆以后改善是否足够？**

只有当位置表不能解释角度或结构变化时，再增加角分布、首次反射路径或更复杂的腔体模型。

## 4. 用真实波形识别前端，而不是无限堆假设参数

首先采集不同光强下的稳态输入输出、上升与下降阶跃、饱和恢复、暗噪声和漂移；再选择能够解释这些数据的模型。

这样“固定带宽”“电流相关带宽”“多极点”才有明确依据。

## 5. 将长片采集作为独立验收项目

至少验证样本计数、文件索引、断网、磁盘满、停止与恢复、重复段和缺失段标记。**图像看起来连贯，不等于数据链完整。**

# 十一、建议按这个顺序整改和验收

| 顺序 | 任务 | 应达到的验收结果 |
|---|---|---|
| **1** | 修正或限定随机 PMT—对数前端模型 | 固定物理条件，细化时间步后统计结果收敛 |
| **2** | 统一 RTL 与文件层样本序号 | 回绕、复位、丢包后仍能唯一识别样本 |
| **3** | 修复窗外轨迹并拆分各类窗口 | 片外照明、关光、行头恢复有明确物理含义 |
| **4** | 增加 ZL80 运动与收光模型 | 能输入实际振镜轨迹、编码器数据和积分筒响应 |
| **5** | 打通实测导入与独立标定验证 | 不借助内部真值，解释未参与拟合的测量数据 |
| **6** | 完成未知长度流式采集与交付测试 | 内存有界，故障后数据边界可追溯，干净安装可运行 |

这几个关口比“再增加多少测试”更重要。测试数量可以增长，但每个新增测试都应回答一个具体的工程风险。

# 十二、现在怎样运行它，才不会误解结果

下面是按仓库现有接口整理的 Windows 操作方式，**不是本次已经执行的安装记录**：

```bat
git clone https://github.com/additivefab/ScanSim.git
cd ScanSim
git checkout 3d05e9e801be55d53c89c4933d8b5359ccc00577

py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev,legacy]"

.venv\Scripts\python -m ruff check .
.venv\Scripts\python -m pytest -q
.venv\Scripts\zlscan --help
```

先跑数字闭环，再跑少量物理行：

```bat
.venv\Scripts\zlscan run --mode digital --out review_digital
.venv\Scripts\zlscan run --mode physical --lines 8 --out review_physical
.venv\Scripts\zlscan serve
```

这些入口与安装依赖均来自当前 README 和命令实现。RTL 相关测试还需相应外部仿真器，不能把安装 Python 依赖理解为所有外部工具也已安装。 

使用时注意两点：

**`run --mode physical` 的基本输出是采集码值和完整性结果，不等于已经完成定量密度标定。**密度图要继续经过参考扫描、`calibrate` 和 `reconstruct`。

**`serve` 打开的是新建演示运行，不会自动打开刚才的 `review_physical`。**当前已保存结果与在线工作台之间，还需要补统一入口。

## 最终建议

**继续使用 ScanSim，但把当前版本定位为“可重复的研究级仿真与数据链框架”，不要提前称为“已验证的整机数字孪生”。**

它最值得保留的是：**透射率域建模、观测与真值分离、跨行状态、可重复随机数、标定绑定、原始数据完整性和可追溯重建。**

接下来最值得投入的不是更多演示页面，而是三件事：

**先解决带噪对数模型的步长问题；再补齐振镜、积分筒实测响应和编码器；最后把这些模型与真实波形、真实底片结果做独立验证。**

完成这些以后，它才会真正帮助我们判断：**80 mm 便携机应该扫多快、需要多少有效光子、积分筒要做到多均匀，以及哪些误差能够校正、哪些必须从硬件上消除。**
