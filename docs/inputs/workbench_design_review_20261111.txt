阅读说明
评审依据是用户上传的《激光底片扫描仪仿真软件开发方案 V4》。本次没有获得包 A、包 B、审查包的实际代码、原始波形、原理图或测试记录。因此，V4 内记载的复跑结果、硬件事实和性能微基准，在本报告中均作为“文件报告的情况”，不冒充本次独立验证。

本文将三类内容分开：V4 已写明的设计、对这些设计的评审判断、为新增可视化需求提出的设计建议。外部资料只用于核实 ADC 时序、PMT 时间响应及候选软件组件能力，不补填项目中未知的器件配置、光路或测量结果。

附带 HTML 的定位是评审交互方式：它使用独立编写的合成玩具模型，不读取 V4 数据、不连接设备，也不是已标定的物理仿真。
第一部分：当前 V4 方案的评估
1. 核心结论
V4 可作为仿真内核的开发基线，但还不能直接支撑“能任意拖动时间轴的数字孪生式工作台”。建议保留内核架构，增补 V4.1 的时域观测、回放和前端契约。

缺的不是一个三维外壳，而是“任意时刻可查询、跨域时间可对齐、历史状态可恢复、样本去向可追踪”的数据和运行机制。

V4 第 5.4—5.8 节已经给出多速率时间、连续状态、确定性随机数和不同计算模式，这是非常好的基础。但第 7.19 节仍将界面主要描述为报告与观察器，第 10 节将增强观察器放入最后的可选工具化阶段，第 12.2 节也把桌面界面留到后期决策。对于用户本次明确提出的使用方式，这一优先级需要调整。[V4 §5、§7.19、§10、§12.2]

推荐的产品定位是：
以统一时间轴为核心，连接光路、器件状态、模拟波形、数字事件、缓存传输和成像结果的多物理域仿真工作台。

第一版采用示意光路和可计算的行为模型；与实际设备身份、配置和测量数据绑定以后，再逐步增强为设备级数字孪生。三维外观并不构成物理可信度的证明。

3. 应在开工前收紧的八项问题
3.1 前端从可选工具化提升为基础能力
本次需求要求：停止在任意时刻，观察每个节点的状态；拖到过去仍保持同一条轨迹；选中一个码字后能找到它的采样时刻；放大到纳秒后，不把插值当成观测。

这些要求会反过来决定仿真输出格式和状态接口。应在阶段 0—2 冻结观测契约，阶段 2 就提供二维时序界面。桌面安装包和高精度三维资产仍可后置。
3.2 物理模型的实现粒度还需明确
V4 已列出很多机制，但“对数级电流域状态方程”“PMT 下垂”“任意极零点滤波”等还不是完整的可实现规格。对每个启用的模型，应补齐：输入输出单位、状态变量、方程、参数来源、数值更新方法、初值、适用带宽、误差控制和验证算例。

特别建议显式固定底片成像顺序：
光学密度 D(x,y)
  → 透射率 T(x,y) = 10^(-D(x,y))
  → 与光斑/眩光的空间权重积分
  → 探测器接收功率
  → 光电与电路响应
不能把“先在密度图上平均”默认等同于“先平均透射光再取对数”。V4 没有提供可据此检查的代码，因此这是需要补充的实现约束，不是已证实的代码错误。
3.3 “微基准外推”不能升级为“整幅实测性能”
V4 在第 1.2 节明确未运行整幅仿真；第 5.6 节和风险表中的约 5.5 分钟来自每细步 340 ns 与约 9.6×10⁸ 步的外推。[V4 §1.2、§5.6、§11]

计算本身量级成立：

340 ns/步 × 9.6×10^8 步 = 326.4 s ≈ 5.44 min。

但它不覆盖新增非线性状态、随机数、迹线写盘、检查点、压缩、查询与界面交互。该步数相对于 7000×8600 像素，隐含每像素约 16 个细步；在纳秒局部细化或模型增强后，不应继续假定该倍数不变。

建议将性能验证拆成“原内核基准”“打开观测后的端到端运行”“拖动与缩放交互”三套测试，分别记录硬件、模型配置、步长、输出字段、存储介质和冷/热缓存条件。
3.4 平移改善支持“时间对齐很重要”，但不能直接给出误差占比
文件记载包 B 的 RMSE 约 0.572，整体平移约 2.2 像素后约 0.21。这说明对齐误差值得优先处理，但最佳平移不等同于从实机可观测信号中标定出的电路延迟，也可能吸收几何映射和采样对齐的误差。[V4 §1.2、§2.3、§10 阶段4]

RMSE 不是可直接加减分摊的总量。多个误差机制可能相关、互相补偿。应在相同 ROI、掩膜、采样和标定条件下做配对消融；需要分解时使用 MSE 与交互项，并说明归因方法。不能把两个 RMSE 的差简单称为延迟贡献。
3.5 真值隔离测试需要限定条件
V4 写到“改动真值镜面号、坐标、功率，重建不变”。这一条应改为：
固定已生成的可观测原始数据、控制记录和允许的标定输入；只替换重建无权读取的真值文件或隐藏元数据，重建结果应不变。

不能改变真实光功率并重新生成 ADC 码流后，还要求重建不变。后者改变了算法的合法输入，反而应可能产生不同结果。这是测试语义的修正，不是反对真值隔离。[V4 §4.5、§9.1]
3.6 纳秒观察所需的快时间模型尚未完整定义
V4 的 PMT 重点是统计倍增、暗信号和增益恢复，没有明确规定电子渡越时间、渡越时间分散和单电子脉冲响应。对于平均电流和像质权衡，这未必是缺陷；但若界面要宣称真实地显示纳秒级光电响应，就必须补充模型和参数来源。

Hamamatsu 的资料将 PMT 电子渡越时间、上升时间和渡越时间分散分别定义，且这些特性与结构及工作条件有关。不能根据“用了 PMT”就给所有设备设置一个统一纳秒延迟。[S2]

建议将快速响应做成可选层，不能确认时显示“未建模 / 假设”，而不是生成看似精确的电子运动。
3.7 证据不足与模块研发不应相互阻塞
继续保留 hardware_verified 的整机严格门槛；同时新增模块级验证状态，例如“ADC 测试码功能模型通过”“接口电平未决”“模拟响应仅假设”。

这样，在缺少对数板资料时，数字链与前端仍能在研究模式中推进；但页面不能把局部通过包装成整机已验证。
3.8 任意回放不能依靠保存全部高频量
假设 20 路观察量、每路 float32，并覆盖 V4 外推的 9.6×10⁸ 个细步，仅数值载荷约为：

20 × 4 × 9.6×10^8 = 76.8 GB。

这是假设记录策略下的未压缩存储量，不是必然的内存占用，也不是实际测得的数据大小。它说明应提前设计选择性记录、分块存储、波形摘要和检查点回放，而不是把完整运行全量塞进浏览器。
第二部分：满足用户需求的 V4.1 前端与运行架构
4. 工作台的基本形态
推荐“二维工程图为主、三维空间视图可切换、虚拟示波器常驻、底部多尺度时间轴”的布局。第一版无需等待整机 CAD。

├──────────┬───────────────────────────────┬───────────────────┤
│ 组件树   │ 光路与器件视图                │ 当前组件探针      │

│ 数字链   ├───────────────────────────────┤ 样本因果追踪      │
│          │ 虚拟示波器 / 数字逻辑波形     │ 采样 → 输出 → 接收│
│ 图像     │ 光功率、电流、电压、码字      │ 缓存 → 主机 → 像素│

├──────────┴───────────────────────────────┴───────────────────┤
│ 实验总览 → 帧 → 行 → 像素 → ADC 拍 → 纳秒事件                 │
│ 播放 / 暂停 / 单步 / 精确跳转 / 缩放 / 事件定位 / A-B 游标     │
└──────────────────────────────────────────────────────────────┘
只有一个仿真时间游标。 光路、数值、波形、图像和样本追踪必须都由同一 run_id + epoch + cursor_time 驱动。浏览器刷新时钟只决定何时画下一帧，不能成为物理过程的时间来源。

二维视图负责讲清连接关系，三维视图负责讲清空间位置，波形视图负责支持工程判断。三者共享组件和信号标识，不能各维护一套数据。

所有颜色之外还应提供文字或图形状态，避免仅靠红绿判断正常与异常。建议默认隐藏非关键探针，以免首页变成所有参数同时出现的监控墙。
6. 必须分开的三种显示语义
6.1 同时刻观察
问题是“在 t 时刻，整机各处分别处于什么状态？”

各组件显示 t 时刻自己的值。此时 PMT 正在响应前面的照明，ADC 正在采样前端的当前输入，同时输出更早的样本；主机还可能在接收上一行的数据。这些差异应被保留。
6.2 样本跟踪
问题是“这个码字如何从采样进入 FPGA、缓存并到达主机？”

选中 sample_id 后，显示它沿数字链的多个时间戳。可以高亮相关组件和波形位置，但不应为了让箭头齐步前进，把所有链路的延迟拉成一样。
6.3 因果回溯
问题是“这个像素或码字受到哪些此前输入与状态的影响？”

对线性时不变近似，可以用响应核表达：

y(t) = ∫ h(τ) x(t−τ) dτ。

因此 ADC 一个采样值可能依赖此前一段光功率、电流和前端状态，而非唯一一个光子。理论长尾若被截断，必须给出截断误差及剩余状态影响。非线性环节只显示已定义的依赖范围或扰动分析结果，不伪造通用线性权重。

这三种语义应有明确的模式名称，不在同一画面中隐式混用。
7. 纳秒级时间轴的正确含义
7.1 四种精度必须同时展示
精度	定义	例子
时间表示分辨率	内部能表示多细的时间戳	1 ps tick 或带分数偏移的时钟计数
交互定位分辨率	游标能移动多细	1 ns 步进
模型时间分辨率	求解/事件模型实际支持多细	自适应模拟步长，8 ns ADC 采样
测量时间能力	实测采样、带宽、触发与对齐不确定度	由仪器与测量设置给定，未知时为空


把游标定位到 1 ns，并不能把 8 ns 一次的 ADC 数据变成每纳秒一条新观测。把曲线画得光滑，也不能证明模拟求解器具有相同精度。

生产界面建议显示：当前信号的原始采样间隔、模型有效范围、是否插值、是否摘要、时间基准以及测量对齐不确定度。没有数据的区间显示空白或明确的“未记录”，不自动补成真实测量。
7.2 AD9268 的具体例子
ADI 手册列出 AD9268 的 80/105/125 MSPS 等级。对于假设正在以 125 MSPS 工作的场景，采样周期为 8 ns。手册 Table 4 列出的 CMOS 流水线延迟是 12 拍，LVDS 的 A/B 通道为 12/12.5 拍；还另列了输出传播延迟等参数。[S1]

因此，CMOS 125 MSPS 情景下，12 拍相当于 96 ns，但不能把“采样至全部系统数据可见”的总延迟一律写成 96 ns。实际事件关联必须依据所选输出模式、时序图、DCO/寄存器设置、接收方式等确定；各延迟只计一次。

至少保存：
sample_time        模拟输入被采样的时间
adc_output_time    与该样本关联的输出有效时间
fpga_capture_time  FPGA 捕获该样本的时间
host_arrival_time  主机收到承载该样本的数据的时间
这四个时间不能只用一个 timestamp 字段代替。手册规格不是本机 ADC 模块的配置证据。
7.3 光学与 PMT 的快时间范围
第一层采用“功能光路 + 功率流”，不承诺完整几何追迹。若需要可信的光传播延迟，应提供路径长度及适用的传播模型；对光脉冲包络在介质中的传播，应考虑群延迟等相关参数，而不是按屏幕画出的线段长度计算。

第二层可加入经声明的光程延迟、PMT 快速响应、前端脉冲响应与 ADC 孔径模型。第三层才是低计数、短时间窗的单事件统计。V4 已将 event 模式限制为短片段，该边界应继续保留。[V4 §5.8]

未知真实光路、PMT 型号或快响应参数时，仍然可以做假设场景，但必须把假设标在画面上，不能作为实机结论。
8. 时间轴交互规格
时间轴应采用“总览 + 当前窗口 + 精确定位”三层，而非仅有一个覆盖整次扫描的滑块。

总览展示预热、暗、白、标定、样片、复核、排空等实验阶段；中层展示帧和扫描行；细层依次显示像素覆盖、模拟响应、ADC 采样及输出、FPGA 接收拍。

建议支持的核心操作：播放/暂停；前后 1 ns 或可配置步长；上/下一 ADC 采样；上/下一行；上/下一异常事件；直接输入时间或样本序号；缩放到当前选区；A/B 游标与 Δt；从像素跳到相关样本和时间范围。

播放速度用“每个现实秒推进多少仿真时间”表达，例如 100 ns/s 或 10 µs/s。不要只显示 0.1×，却不说明相对哪个基准。

暂停应冻结与仿真过程相关的所有动画。相机旋转、鼠标悬停等纯交互动作可以继续；光子/电子/数据流的示意动画不能绕开暂停状态继续播放。

拖动到未计算区间时显示“未计算”；已有摘要但没有原始记录时显示“摘要”；需要回放计算时显示对应状态。浏览器不应以一段随意生成的动画填补这些区间。

9.1 研究探针不能变成真值泄漏通道
V4 数据流中“评价唯一可读真值”的表述，应增加受控的研究观察例外：评价器和授权的只读研究观察器可以读取真值；标定、重建、实机控制路径仍不能读取。

建议采取独立数据集/路径和接口白名单，而不是仅在页面隐藏一个选项。修改探针配置、打开研究视图、回看历史，都不得改变模型输入或随机数轨迹。

从研究视图导出的报告、截图和探针数据也应带上“仅仿真真值”的来源标签。把 UI 状态保存后重新导入，不能把真值字段转换成标定输入。
9.2 场景外观与物理拓扑分开
每个组件共享稳定的 component_id，但分别记录外观姿态、物理参数、输入输出端口、状态字段和证据。

调整图上方框的位置只改变布局；改变真实镜头位置属于物理配置修改，应生成新的运行或实验时期。用户本次要求的是拖动时间轴，因此第一版不必做任意拖拽器件并实时重新计算光学的 CAD 式编辑器。

10.2 时间与身份
使用 run_id + branch_id + session_id + epoch + channel + sample_index 标识样本，不能仅用行号或镜面号。

建议事件时间采用可配置整数 tick，例如整数 ps；ADC 等周期性事件优先保留时钟域、计数、相位及频率定义。对于不能整除 tick 的周期，通过整数商余数/相位累计器或有理数定义产生事件，避免每拍独立舍入后累计漂移。更细的抖动研究应显式提高时间分辨率或保留分数偏移。

浏览器不使用浮点 Unix 纳秒作为唯一时间真值。JavaScript 的安全整数范围为 ±(2⁵³−1)，因此大整数时间建议用 BigInt 或十进制字符串传输，绘图时再将相对于当前视窗原点的小偏移转换成 Number。[S6]

实测的跨时钟对齐应带上时钟映射、漂移和不确定度；若不能建立纳秒级对齐，不得在图中表现成已知的纳秒先后顺序。

11. 如何实现向前、向后与任意跳转
11.1 不倒着积分
滤波、恢复、漂移、随机倍增等状态不应通过“倒放微分方程”求过去。回看使用已有迹线；需要恢复完整内部状态时，从目标之前最近的有效检查点恢复，再按原命令与原随机轨迹向前重放。
目标 t
  → 找到 checkpoint(t0)，其中 t0 ≤ t
  → 恢复完整状态和待处理事件
  → 恢复配置、时钟、随机源和日志位置
  → 向前推进至 t
  → 发布只读状态与局部迹线
检查点不仅包含模拟滤波器，还要包含光源/机械状态、随机源状态或计数、时钟相位、ADC 在途样本、CDC/队列状态、未处理事件、控制命令偏移、模型版本和配置校验值。

检查点间隔应依据恢复代价与存储预算设置，可在配置变化、阶段切换和异常附近加密。不要为所有模型硬编码一个固定“每行一份”规则。
11.2 区分精确回放与更精细的重新仿真
同一模型、同一离散化、同一配置和随机实现下，回放应保持可复现；数字结果应按契约逐位一致，模拟浮点结果在固定环境下尽可能一致，并声明允许的数值容差。

如果把模拟步长从 8 ns 改为 1 ns，或把统计时间箱改成单事件模型，那是一个新计算分支，不是把原来的随机轨迹“放大”。不能自动承诺逐点相同。需要跨步长耦合时，应明确设计嵌套随机增量、事件桥接或其他一致性机制，并另做收敛/统计测试。
11.3 改参数时不覆写历史
纯视角、配色和曲线显隐不产生新运行。改变激光功率、PMT 增益、模拟响应、ADC 配置等应创建新分支或记录有生效时刻的控制事件。使用旧标定是否仍有效必须重新检查。

这让 A/B 对比可以真正解释“哪个参数发生了变化”，而不是界面悄悄替换原来的结果。
12. 数据量与性能策略
12.1 记录分层
数据	默认策略
ADC 原始码流与完整性信息	按运行需求流式记录，保留原始采样身份
关键数字/控制事件	精确记录事件和时钟域，不复制成每纳秒一条状态
低速机械/温漂状态	按本身变化尺度记录，带插值策略
高速模拟内部量	选择关键探针；全局摘要与局部细节结合
整帧图像	分块/多层图像，按视口加载
状态检查点	按恢复代价和可复现要求记录
单光电子事件	仅在明确的短窗 event 模式记录


12.2 波形缩放不能丢异常
全局视图使用多层级 min / max / first / last / count 摘要，必要时保留事件标记。均值降采样可能隐藏短脉冲、削顶和溢出，不能作为唯一表示。

数字逻辑使用跳变和持续区间表达；不要对 0/1 信号做平滑插值。局部放大到原始尺度后显示实际采样点、保持阶梯和事件边沿。

摘要只能用于显示，不能替代标定、重建或误差评价的原始数据。查询响应必须告诉前端当前取到的是哪一层表示。
12.3 前端与仿真解耦
仿真可以高速向前算，浏览器按屏幕刷新率画；也可以暂停计算，浏览器只回看数据。后端不必每产生一个 ADC 码就推送一次 WebSocket 消息。

进度与运行状态可低频推送；波形按当前窗口批量查询；大数组使用二进制传输；解析和摘要优先放到 Web Worker，避免阻塞拖动与点击。[S7]

缓存范围、磁盘吞吐、探针数量和最长回放跨度均应进入预算器。V4 的板端 512 MiB 与工作站预算继续独立；这里新增的是工作站迹线存储和前端显示预算。

原文 22—29 人周估算没有充分覆盖现在新增的时域数据服务与前端验收工作，因此不能直接沿用为升级后项目的总量承诺。建议先对 M0—M3 做工作分解，再重估三维与实测扩展。
15. 第一版不要同时追求的能力
第一版不必包含完整光学 CAD、真实镜头处方重建、逐光子全帧追踪、逐电子三维轨迹、晶体管级模拟、全板电磁/时序求解、在线控制真实激光与高压。

保留 V4 对签核级仿真的边界，但把“完全不做整机光线追迹”和“可以显示功能光路”明确区分。功能级二维/三维光路并不要求把整个系统改成 Zemax 或 SPICE 的替代品。

如果以后需要真实几何光路，可新增经证据支持的折线/傍轴/外部光学工具结果层；只有其误差和参数得到验证后，才用于物理结论。浏览器中的可视化射线与物理射线追迹始终是不同层次。
16. 最重要的验收清单
编号	测试	通过标准
T01	同一时刻跨视图	光路、探针、波形、逻辑和图像共享同一运行、时期和时间
T02	暂停与多次回看	暂停后仿真动画不漂移；反复定位返回相同记录
T03	ADC 时间语义	采样、输出、接收、到达分别正确；相差一个流水线时不能错认样本
T04	记录不足	原始间隔不足时展示保持/插值标记；缺数据不能伪造
T05	检查点	保存恢复与不中断运行一致；包含 RNG、队列、时钟与待处理事件
T06	观察无扰动	打开/关闭探针、切换视图和拖动不改变仿真及重建结果
T07	真值隔离	固定可观测数据后改变隐藏真值，标定/重建不变；前端导出不绕过合同
T08	窗口区别	片外照明影响前端历史，即使对应码字被数字窗口舍弃
T09	数字故障	溢出、缺包、错位序等能追踪到层级和样本范围，不静默拼图
T10	摘要保真	粗视图仍能看到短脉冲/极值/故障；细视图恢复原始点而非猜测
T11	随机与分支	同轨迹回放可复现；更换步长/机制被标为新分支，不谎称相同随机实现
T12	实测来源	非同次采集不被表现为严格逐点同步；对齐误差显式可见
T13	UI 请求竞争	快速拖动后，迟到查询不能把画面跳回旧时间
T14	性能	在指定机器、数据规模和缓存条件下，分别报告运行、存储、查询与绘制指标


交互指标可以先拟定，例如“已缓存时间窗的定位 P95 不超过 150 ms、常规视图达到 30 fps”，但它们只能作为待验证的产品目标。冷回放延迟需要根据检查点间距和实际模型另行制定，不宜统一承诺。
