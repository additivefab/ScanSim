# ZLRAW 0.1 原始码流格式（草案，待与 FPGA 侧共同冻结）

状态：**草案**。版本号保持 0.x，直到 FPGA 侧确认字段含义和字节布局。实现：`src/zlscan/io/rawstream.py`；测试：`tests/unit/test_rawstream.py`。

这份文档给写采集逻辑和上传固件的人看。它回答"仿真产生、重建消费的数据是什么样子"，不声称实机已经这样输出。

## 1. 文件结构

```text
文件   = 前导 "ZLRAW0.1"（8 字节）| u32 会话头长度 | 会话头（UTF-8 JSON）| 数据块 *
数据块 = 64 字节块头 | 载荷
载荷   = sample_count 行，每行 = 通道数 × bytes_per_sample 字节（通道交织）
```

全部多字节整数为小端。当前只支持每样本 2 字节（`uint16`）；码值只放低 `bits_per_sample` 位。

## 2. 会话头（JSON）

| 字段 | 含义 |
|---|---|
| `schema_version` | 固定 `"0.1"` |
| `session_id` | 会话编号；每个块头里必须带同一个值 |
| `created_at` | 创建时间 |
| `hardware_hash`、`firmware_hash`、`wiring_rev`、`register_dump_hash`、`calibration_id` | 未知为 `null`，不用空串 |
| `channel_roles` | 通道号 → `"signal"`、`"reference"`、`"unused"` 或 `null`（用途未知） |
| `clock_domains` | 每个时钟域的编号、标称频率（分子、分母）、说明 |
| `coding` | `offset_binary` 或 `twos_complement` |
| `bits_per_sample`、`bytes_per_sample` | 例如 16 与 2 |
| `value_domain` | 固定 `"raw_code"`：这里存的是 ADC 原始码，不是密度 |
| `windows` | 光学窗口与数字保留窗口的定义 |
| `origin` | `SIMULATED` 或 `MEASURED` |

## 3. 块头（64 字节）

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | `magic` | `ZLR1` |
| 4 | 2 | `version` | 块格式版本，当前 1 |
| 6 | 2 | `header_len` | 64 |
| 8 | 8 | `session_id` | 与会话头一致 |
| 16 | 4 | `epoch` | 时期；配置或复位后加一 |
| 20 | 4 | `block_seq` | 块序号，从 0 起每块加一，贯穿整个会话 |
| 24 | 2 | `channel_mask` | 每位一个通道；载荷里的通道按位序交织 |
| 26 | 2 | `clock_domain` | 该块样本所属的时钟域 |
| 28 | 2 | `flags` | 见下 |
| 30 | 2 | 保留 | 写 0 |
| 32 | 8 | `first_sample_index` | 第一行样本在该时钟域内的采样序号 |
| 40 | 4 | `sample_count` | 行数（每通道样本数） |
| 44 | 4 | `payload_bytes` | 必须等于 行数 × 通道数 × 每样本字节数 |
| 48 | 4 | `line_number` | 行号，**仅供参考，不是主键**（复位后会重复） |
| 52 | 4 | `payload_crc32` | 载荷的 CRC-32（zlib 多项式） |
| 56 | 4 | 保留 | 写 0 |
| 60 | 4 | `header_crc32` | 覆盖第 0–59 字节 |

标志位：`0x01` 行首、`0x02` 行末、`0x04` 帧首、`0x08` 帧末、`0x10` 溢出后的第一块、`0x20` 时期起始。

## 4. 读取规则

读取方不会悄悄拼接。每一种损坏都有确定的处理：

| 情形 | 处理 |
|---|---|
| 文件前导不对、块魔数不对、块头 CRC 不对、版本未知、头长度不是 64、载荷长度与头不符 | **致命**：停止读取。损坏的块头无法说明下一块从哪里开始 |
| 载荷 CRC 不对 | 报错；这一块**不交付**；生成一条精确的丢失记录（首末样本序号来自可信的块头） |
| 块序号倒退或重复 | 报错；该块不使用 |
| 块序号跳变 | 报错；丢失范围由样本序号的连续性给出 |
| 样本序号出现缺口 | 一条精确的丢失记录 |
| 样本序号倒退 | 报错；该块不使用 |
| 时期变化但没有 `0x20` 标志 | 报错（数据仍交付，调用方必须拒绝使用） |
| 块属于别的会话 | 报错；该块不使用 |
| 文件在块中间结束 | 报错；已完整的块保留 |

守恒：交付的样本数 + 丢失记录覆盖的样本数 = 写入的样本数（测试固定）。

CRC 只保护它被生成之后的数据一致性，**不证明 ADC 采样本身正确**。

## 5. 包 B 的无头格式

包 B 的 `raw_roi_u16le.bin` 没有头：行优先、小端 `uint16`、只含有效区。适配器 `read_headerless_u16(path, nx, ny, samples_per_pixel, coding)` 要求调用方明确给出尺寸与码制；文件大小与尺寸不符时报错，不补齐也不裁剪。

## 6. 需要 FPGA 侧回答的问题

| 编号 | 问题 |
|---|---|
| Z1 | 实际的字节序、每样本字节数、通道数与通道交织方式 |
| Z2 | CRC-32 在哪一级生成（PL、PS 还是上位机）？如果在 PS 或上位机生成，它只保护传输，不保护采集 |
| Z3 | 一个块对应什么：一行、固定长度、还是一个 DMA 描述符？`line_number` 与行末标志如何得到 |
| Z4 | 时期与块序号由谁维护；复位后是否从 0 重新开始 |
| Z5 | 溢出发生时，硬件能否给出丢失的样本数，还是只能置一个粘滞标志 |
| Z6 | 样本序号是否由 PL 计数器给出，宽度多少，回绕如何处理 |
| Z7 | 事件（行同步、编码器、配置生效）是否与样本同流，还是另一条流 |
| Z8 | 实际的 ADC 码制与位数 |

在这些问题有答案之前，本格式只用于仿真与重建的内部接口。
