# 05 编码规范

## 1. 语言与工具

| 项 | 规定 |
|---|---|
| Python | 3.11 及以上；本机当前为 3.14 |
| 打包 | `pyproject.toml`，`src/` 布局，包名 `zlscan`，命令入口 `zlscan` |
| 格式与检查 | `ruff format`、`ruff check`（规则集在 `pyproject.toml` 里定，至少启用 E、F、I、B、UP） |
| 类型 | 公共函数与合同类必须有类型标注；不强制全量类型检查 |
| 测试 | `pytest`；性质测试可用 `hypothesis` |
| 前端第一级 | 原生 HTML、SVG、Canvas、JavaScript，单文件、离线、无外部依赖 |

## 2. 允许的依赖

| 类别 | 依赖 |
|---|---|
| 运行 | `numpy`、`scipy`、`pydantic`（v2）、`h5py`、`tifffile`、`Pillow` |
| 开发 | `pytest`、`hypothesis`、`ruff` |
| 可选（用到时才加，加之前在 DECISIONS.md 记一条） | `numba`（热点加速）、`cocotb`（RTL 协同）、`matplotlib`（报告图）、`fastapi` 与 `uvicorn`（第二级工作台） |

清单之外的依赖需要用户同意。不引入深度学习框架、数据库、分布式计算框架。

## 3. 代码风格

- 标识符、docstring、代码注释用英文；面向用户的报告、界面文字、`docs/` 用中文。
- 一个函数只做一件事。旧包那种一行多语句的压缩写法不要沿用。
- 物理量的变量名带单位后缀：`_s`、`_hz`、`_m`、`_um`、`_v`、`_a`、`_w`、`_ticks`、`_px`。无量纲量不加后缀。
- 配置用 pydantic 模型，不用裸字典传参。
- 不写"以防万一"的兼容代码和从不触发的分支。
- 注释只写代码本身表达不了的约束或原因。

## 4. 数值规则

- 时间主键用整数刻度（见 `03_contracts.md`）。不比较浮点时间是否相等。
- 浮点比较必须给出容差，并在测试里说明容差的来源。
- 不静默夹紧。越界值要么报错，要么置标志位并保留原值供诊断。
- 不捕获宽泛异常后继续。配置错误、数据损坏要明确失败。
- 随机数只通过 `engine` 提供的工厂获得；不调用全局的 `numpy.random.*` 函数，不用墙上时钟做种子。
- 数组默认 `float64`；落盘的图像与迹线可用 `float32`，在合同里声明。
- 大数组不整帧驻留：按行块处理，函数接口接受并返回块。

## 5. 真值隔离的写法

- `truth` 包内的东西不通过参数、全局变量、缓存、文件路径、环境变量传给 `calib` 与 `recon`。
- `calib` 与 `recon` 的入口函数只接受：原始码流读取器、可观测事件流、标定文件、`instrument` 与 `hardware` 配置。
- 评价代码放在 `metrics`，由它去读真值；不要在 `recon` 里顺手算一个"与真值的误差"。

## 6. 未知值与证据

- 硬件参数用 `Param`（见合同第 1 节）。未知写 `None`。
- 任何函数拿到 `None` 的必需参数时，`hardware_constrained` 模式下抛出明确的错误，错误信息指出缺哪一项资料。
- 示例数值只出现在 `config/presets/` 下标明 `ASSUMED` 的预设里，不写进代码默认参数。

## 7. 命令行与输出

- 每个子命令的输出目录里写 `run.json`（合同第 12 节）。
- 人看的摘要打印到标准输出，机器读的结果写文件；出错返回非零状态。
- 未实现的子命令返回非零并说明"尚未实现"，不得静默成功。

## 8. 测试要求

- 每个任务的验收项都有对应测试，测试名体现它在验证什么。
- 测试不依赖网络，不依赖本机绝对路径。
- 慢测试（超过约 10 秒）标 `@pytest.mark.slow`；遗留回归标 `@pytest.mark.legacy`；性能测试标 `@pytest.mark.perf`，默认不跑。
- 修 bug 先写一个能复现它的测试。

## 9. 提交规范

```text
<阶段-任务号> <类型>: <一句话说明>

<可选正文：为什么这样做；规格有无改动；实际运行了哪些测试>
```

- 类型：`feat`、`fix`、`test`、`docs`、`refactor`、`chore`。
- 例：`S0-T03 test: add legacy package A regression harness`。
- 一个提交只做一件事。规格改动与对应代码改动放在同一个提交。
- 提交前 `ruff check .` 与 `pytest -q -m "not slow"` 通过。
- 不提交生成的大文件。`evidence_runs/` 里只提交记录与校验值，大输出进 `.gitignore`。
- 不加署名行。不改写已有历史，不强制推送。

- 新模型的 `ModuleSpec` 与 `04_physics_spec.md` 里的方程保持一致。
