# 07 证据规则

这个项目反复出过同一类错误：把照片上的读数、教学示例值、没跑过的测试，写成了设备事实或已验证结论。本文件的规则就是为了不再犯。

## 1. 三句话原则

1. 不知道就写"未知"，不填数。
2. 没跑过就写"未执行"，不写通过。
3. 推断、假设、估读都要标出来，并写明它依赖什么。

## 2. 禁止默认项

下列说法都曾被当成事实使用，后来被证明证据不足。它们不得作为任何配置的默认值、任何验收的基准、任何报告里不带标注的陈述。

| 禁止的默认 | 实际情况 |
|---|---|
| 行周期 0.7 ms / 行频 1.4 kHz | 从示波器截图估读，已撤回。屏幕上可读的 "80.0us" 是窗口时基，主时基被遮挡 |
| 模拟输出摆幅 4.28 V 或 4.3 V | 只是屏幕游标差。测点、探头倍率、单端或差分关系都未知 |
| ADC 采样率 125 MSPS | 模块丝印上的标称能力，不是实测工作点 |
| ADC 采样率 20 或 50 MSPS | 两套旧包的教学示例 |
| 载板 DAC 控制 PMT 高压 | 去向未知。可能是高压、前端增益或偏置、激光 |
| 第二个 ADC 通道是激光参考光 | 没有证据表明装了参考探测器 |
| 扫描光学单元来自某品牌设备 | 只是丝印线索的猜测 |
| 某块小电路板是行同步探测器 | 候选解释 |
| 透明板状件是导光体 | 候选解释 |
| 6 面转镜、10000 rpm | 旧包示例 |
| 635 nm、1 mW、增益 1000、QE 0.15 或 0.2 | 旧包示例 |
| 7000×8600、4000×5000、50 µm | 性能测试算例，不是产品规格 |
| 高密度读数平台主要由眩光造成 | 待验证的候选机制之一 |
| 示波器波形的 U 形底说明弱光时响应变慢 | 待解释的现象，可能是片边遮挡 |
| 延迟是包 B 误差的主因 | 配准消融只提示对齐误差占重要部分，成因未分离 |
| 整幅仿真约 5.5 分钟 | 由旧模型单步耗时乘以假设步数外推，整幅从未执行 |
| 重放一行约 38 到 220 毫秒 | 同样是外推 |

这些数值可以出现在标明 `ASSUMED` 的研究预设里，用于示例和回归。

## 3. 证据类别

| 类别 | 例 | 能支持什么 |
|---|---|---|
| 项目文本 | 调研记录的文字 | 作者的描述 |
| 图片观察 | 丝印、屏幕读数 | 该物体上印了或显示了什么 |
| 原理图标称 | SP2 原理图的网络与器件 | 该版本板卡的设计，不等于实物实测 |
| 外部手册 | AD9268 数据手册 | 器件的能力范围，不等于本机配置 |
| 设计推导 | 由其他参数算出的量 | 取决于它依赖的参数 |
| 假设 | 旧包示例值 | 仅供研究模式 |
| 实测 | 带测量条件的数据文件 | 该条件下的设备行为 |

常见的错误升级，一律禁止：

- 图片上有某个字样 → 系统正以该参数运行。
- 手册上有某个模式 → 本机启用了该模式。
- 拟合出了数值 → 该参数被唯一确定。只有组合可辨识时，只报告组合（例如激光功率 × 集光效率 × PMT 增益）。
- 模型经实测标定 → 模型的输出是"测得"的。
- 没有发现冲突 → 通过。电气与接线检查用三态：通过、失败、未决。

## 4. 运行结果的状态

| 状态 | 含义 |
|---|---|
| 作者报告 | 别人的文档里写的，本工程没有重跑 |
| 独立重跑 | 本工程重跑过，有完整证据记录（见 `06_testing.md` 第 7 节） |
| 实机测量 | 来自设备，带测量条件 |

没有完整记录的重跑只能算"作者报告"。

## 5. 五种"通过"

| 状态 | 由谁产生 |
|---|---|
| 文档一致性通过 | 本工程的规则检查 |
| 行为模型通过 | 本工程的测试 |
| RTL 功能协同通过 | 本工程的协同仿真 |
| 综合与时序通过 | 外部工具报告，本工程只登记 |
| 实机验证通过 | 实机测量，本工程只登记 |

任何一种都不能代替另一种。界面和报告里不得用一个总状态把它们合并。另设模块级状态（例如"ADC 测试码功能模型通过""接口电平未决"），同样不得汇总成"整机已验证"。

## 6. 配置模式

| 模式 | 规则 |
|---|---|
| `research` | 可用假设值与外推；报告首页显著标注，并列出所有 `ASSUMED` 参数 |
| `hardware_constrained` | 必需的硬件参数缺失或仅为假设时拒绝运行。它表示"配置受真实资料约束"，不表示实机已通过 |

## 7. 报告与界面必须显示的内容

- 配置模式与预设名。
- 证据状态汇总：多少参数是假设、手册、实测。
- 哪些验证未执行。
- 每条曲线：原始采样间隔、是否插值、是否摘要、对齐不确定度。
- 研究视图导出的任何内容带"含仿真真值"标签。
- 性能数字带机器、配置、是否外推。

## 8. 代理自身的汇报

- 说"测试通过"之前，这次会话里必须实际跑过，并能给出命令和输出。
- 上一位代理在 PROGRESS.md 里写的"通过"，接手时先重跑确认，再沿用。
- 没做完就说没做完；跳过了哪一步就写明跳过了哪一步。
- 自己之前的结论被证明有误时，直接更正并记入 DECISIONS.md。
